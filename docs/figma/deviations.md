# Deviations from the design: the record

This is the docs site's former "Deviations from Figma" page, saved as it last rendered on
2026-10-28, when it was taken off the public site (M82: the Figma file is internal). It is a
snapshot and is not regenerated. The live sources are still in the repo:

  `12-w3-forms.md` and `13-w4-menu-tabs.md` in this folder;

- the browser degradations, ARCHITECTURE.md §18.2 and `fixtures/floor-lane/RESULTS.md`.

The builder's answers that only the page held (`apps/docs/lib/builder-choices.ts`) are under
"Builder-chosen values" below.

Where the code differs from the Figma file, and why. Generated from the files that own each difference.

Nizivo follows the Figma library, except where a value fails WCAG 2.2 AA, where Figma has no value yet, or where a browser on the support floor cannot do what the design asks. Every difference is listed here, read at build time from the file that owns it; none of it is typed by hand.

## Contrast overrides

Figma variables that the code points somewhere else, mostly to reach 4.5:1 for text and 3:1 for non-text. The contrast matrix in `packages/tokens/CONTRAST.md` checks every pair with any of these in place.

None. Every Figma variable is used as Figma defines it: the 14 contrast overrides the code carried were adopted in Figma with the same values, and removed from the code on 2026-10-18.

## Proposals

None. Every token is a Figma variable or code-owned by nature: Figma adopted 18 of the 19 proposals on 2026-10-18, and the last one, `--nz-text-accent`, was removed before 0.2.0 (use `--nz-text-brand` on page surfaces and `--nz-text-inverse-accent` on `bg/inverse`).

## Builder-chosen values

### D-i: Progress fills for tones Figma does not draw (§15.3)

Adopted 2026-10-14 (builder default; the maintainer can override). ProgressBar, Meter and ProgressRing paint `tone="neutral"` with `icon/secondary` and `tone="success"` with `icon/success` until design supplies the fills

Why: `chart/neutral` is 1.36:1 (light) and 1.41:1 (dark) on `chart/track`, under 1.4.11's 3:1, and the neutral example shows no value text, so the fill is the only cue. `icon/secondary` reaches 3.75 / 5.32 and `icon/success` 4.06 / 5.87 on the track. Figma has no `chart/success`

Evidence: `progress-bar.css`, `meter.css`, `progress-ring.css`; `packages/tokens/CONTRAST.md`. Source: docs/ARCHITECTURE.md §23.4

Two week 4 behaviours differ from the APG patterns, and neither is in the Figma file:

- Enter on a Menu checkbox item toggles it and keeps the menu open, as Space does. The APG menu button closes the menu on Enter. Staying open lets a reader set several columns in one visit (D-ag).

- Tabs arrow keys follow the direction of the `locale` set on `NizivoConfig`, or the `dir` prop on `Tabs.Root`, which overrides it for that strip and the strips nested in its panels (week 7, the maintainer's decision). A `dir="rtl"` attribute set elsewhere on the page alone does not turn them, because nothing reads the DOM: without the locale or the prop, ArrowRight moves to the tab on the left in a right-to-left strip.

### Week 7

Two values that are not in the Figma file, both the maintainer's decisions of 2026-10-16:

- 16 px text in fields under a coarse pointer. Input, Textarea, NativeSelect and the Select trigger use Body/L or Label/L (16 px) instead of Figma's Body/M or Label/M (14 px) when the primary pointer is coarse, because iOS Safari zooms the page into a focused field whose text is under 16 px. The weights are Figma's. Heights stay on the 32/40/48 px scale; a Textarea row is Body/L's 25.6 px line there instead of 21 px. The Select list's rows stay at 14 px. A page that sets `--nz-input-font`, `--nz-textarea-font` or `--nz-native-select-font` replaces the font on every pointer, so it also owns the zoom.

- A minimum size for bare triggers. A `Dialog.Trigger` or `Tooltip.Trigger` with no `render` (its own unstyled `<button>`) is at least 24 by 24 px (`1.5rem`), the WCAG 2.2 2.5.8 minimum, and carries `nz-hit-target` for the 44 px coarse-pointer hit area. Figma draws every trigger as a Button, which is still the recommended composition.

### Week 8

One value that is not in the Figma file, the maintainer's decision of 2026-10-17:

- Alert's dismiss is a small IconButton. Figma draws the close as a bare 16 px glyph with no states. In code it is a tertiary `sm` IconButton: a 32 px button with IconButton's hover and pressed fills and focus ring, and in forced colours its `ButtonText` border. ### Week 9

Figma's file of 2026-10-18 settled several week 3 to week 6 choices (the Select list, the Textarea's padding and height, the chart fills, one border width, the spinner's speed), so the tables above now record Figma's values where they apply. What still differs, with the maintainer's decisions of 2026-10-18:

- The selected Select row keeps a tint. Figma's Select Option draws the selected row with only Label/M Strong and a trailing check. The code also keeps the `--nz-bg-brand-subtle` fill it had (M36: "keep tint, for label, follow figma").

- The Select check's column is always reserved. Figma hides the check on unselected rows and the label takes its place; the code keeps the 16 px column on every row, so selecting never moves the text.

- The Select list is as wide as its trigger. Figma's Select Menu says "matches its width (min 240)"; the code keeps the trigger's width as the minimum, with no 240 px floor.

- A pending Button replaces its label under Reduced motion. Figma's Button says "keep the label"; under Reduced motion the code shows "Loading…" in the label's place instead, so the button keeps its width when the wait starts. The label stays in the accessible name ("Loading… Publishing"). Under default motion the label stays, with the spinner, as in Figma (M37).

- An icon-only pending button shows no text under Reduced motion. Figma's Accessibility page says "Spinner and skeleton loops stop; a text label shows". Button does that. IconButton has no room for text: its spinner stops and `aria-disabled` stays, and nothing visible says it is loading. Show the progress in words next to it (a status line), or use a Button where a label fits (M37: accepted).

- A Textarea's minimum height can be lowered. Figma's 112 px minimum is the default; `--nz-textarea-min-block-size` changes it (for example to `0` for a one-line composer).

### Week 12

The dashboard parts (Figma 04), with the maintainer's decisions of 2026-10-20 (M42):

- The Delta pill is `bg/surface` on a tinted surface. Figma draws the Up pill in `bg/success-subtle`, the same green-50 as `bg/brand-subtle` (and in dark mode all three tints are green-950), so on a tinted KPI tile the pill shows no fill (Figma 04 gap 4). Inside a Card, KpiTile or TrendCard with `tone="brand"` or `"accent"`, every Delta pill is `bg/surface` instead, including the Down pill on an accent tile, which Figma draws in `bg/critical-subtle` and which does show there: the pills in a tinted row match. Its text keeps Figma's colour: `text/success`, `text/critical` and `text/secondary` on `bg/surface` are at least 5.68:1 in light and 5.96:1 in dark.

- A chart's halo follows the surface it sits on. Figma rings the Sparkline's end dot in `bg/surface`, which shows as a white ring on a tinted tile. The halo reads the surface a Card declares (`--nz-surface`), so on a tinted tile it is the tint; outside a Card it is `bg/surface` as drawn.

- `brand` and `accent` look the same in dark mode (both green-950). That is Figma's design, and the code follows it for now (Figma 04 issue 5); it is listed here because it reads like a defect.

## Browser degradations

Found on the browser floor (Chrome/Edge 123, Firefox 129, Safari/iOS 17.5).

D1Firefox 129–131: `light-dark()` with literal colours written directly on a non-inherited property can take the wrong scheme in nested scopes (Firefox bug 1914735, fixed in 132). Nizivo's tokens are unaffected; write theme colours as custom properties.D2Firefox (all versions tested, 129 to 157): an exit transition that ends in `display: none` is instant, because Firefox cannot animate `display` (bug 1834877). Entry animations work. Engine-managed overlays are unaffected; a CSS-only component that needs an exit animation hides with `visibility` instead.D3Firefox 129–157, WebKit 27.2 and Mobile Safari 17.5 have no `overlay` property, so a native popover or `<dialog>` exit is instant there. Nizivo's overlays are engine-managed and stay mounted through `data-exiting`, so they are unaffected; this is why no overlay swaps to the native element yet (§12.4 gate 1).D4Mobile Safari 17.5 (iOS 17.5 Simulator): an exit transition that ends in `display: none` is instant, as in Firefox (D2): `transition-behavior: allow-discrete` parses, but `display` does not transition. Entry animations work, and WebKit 27.2 fades. Engine-managed overlays are unaffected; a CSS-only component that needs an exit animation hides with `visibility` instead.
