# `contracts/api` reference

`contracts/api/**` is the generated, semver'd record of `@nizivo/react`'s public surface
(ARCHITECTURE.md §6, §18.1). `nz api` writes it from the **built** package and the component
manifests. The docs site renders its props, parts, data attribute and hook tables from it, and
nothing else (§18.2). A diff in these files is an API change, which the changeset must classify. The
types are in `schema.ts` next to this file. It has no imports and no runtime code, so the generator
and the docs app both use it with `import type`.

Two builders work from this file in parallel, one writing the files (the generator) and one reading
them (the renderer). Anything this file leaves open is decided in `schema.ts`; anything both leave
open, ask before guessing.

## Files

| File                                    | One per                                                                                   | Type           |
| --------------------------------------- | ----------------------------------------------------------------------------------------- | -------------- |
| `contracts/api/react/<entry>.json`      | JavaScript entry of the exports map: `./alert` → `react/alert.json`                       | `ReactApiFile` |
| `contracts/api/react/index.json`        | the root barrel `.`: every export, each pointing at the file that documents it            | `ReactApiFile` |
| `contracts/api/react/unstable/<n>.json` | `./unstable/<n>`                                                                          | `ReactApiFile` |
| `contracts/api/css/<name>.json`         | stylesheet entry `./css/<name>.css` (and `./reset.css` → `css/reset.json` once it exists) | `CssApiFile`   |

`./styles.css` gets no file: it concatenates the others. `./package.json` and `./css/manifest.json`
get none either. `./augment` is types only and gets `react/augment.json` like any other entry.
Entries without a `component.json` (`.`, `./config`, `./contracts`, `./augment`) have no `component`
field.

`contracts/vocabulary.json` and `@nizivo/tokens/contract.json` stay the sources for attribute
meanings and token types; these files copy what a page needs (an attribute's meaning, a token's
name) so the renderer reads one file per page.

## Determinism

The same build gives byte-identical files on any machine:

- **Keys** are sorted in code-point order at every depth, so `$comment` comes first.
- **Arrays** of named things are sorted in code-point order by their name (`name`, `slot`, or
  `selector` then `property`). Arrays whose order carries meaning keep it, and each says so in
  `schema.ts`: `parts` (manifest order, `Root` first), `parameters` (positional), `signatures`
  (declaration order), `values` (declaration order), variant value lists (manifest order),
  `inherits` and `extends` (clause order), `conditions` (outermost first) and `layers` (file order).
- **Printing:** `printJson` from `packages/tooling/gen/format.ts`, the printer `nz gen` uses: two
  spaces, objects always expanded, arrays of primitives on one line when they fit in 100 columns,
  LF line endings and a final newline. Its output passes `oxfmt --check` unchanged.
- **Header:** `"$comment": "generated by nz api; do not edit"` (the `nz gen` phrasing), and
  `"version": 1`, the version of this format (not of the package).
- **Never written:** timestamps, absolute paths, package versions, hashes. Paths are repo-relative
  with `/` (`packages/react/src/alert/alert.tsx`).
- **Text:** a `description` is the JSDoc text without its tags, as Markdown: lines joined with one
  space, paragraph breaks kept as `\n\n`, trimmed, so rewrapping a comment changes nothing. A line
  that starts a list item (`- `, `* `, `1. `) starts a new line instead, so a list stays a list
  (`mergeProps`), and fenced code keeps its lines. Types are verbatim from the `.d.ts`, which
  tsdown prints with double-quoted string literals.

## Where each field comes from (generator)

| Data                                    | Source                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| exports, props, types, JSDoc            | the public `.d.ts` files under `packages/react/dist`, read with ts-morph 28 (it bundles TypeScript 6.0.2, so no `typescript` import is needed), starting from each exports entry's `types`                                                                                                                                                                                                                 |
| `client`                                | the built `.js` next to the declaring `.d.ts`: `true` when it starts with `'use client'` (`.d.ts` files drop directives)                                                                                                                                                                                                                                                                                   |
| `source`                                | the `.d.ts` path mapped back to `packages/react/src/**/*.{ts,tsx}`                                                                                                                                                                                                                                                                                                                                         |
| `component`, `parts` order, `variants`  | `packages/react/src/<name>/component.json`                                                                                                                                                                                                                                                                                                                                                                 |
| slots and their attributes              | the `data-slot` and `data-*` names the component's modules write (its own folder, plus the `stateAttrs()` its adapter in `src/_engines/**` merges into each part, followed through `engine.ts`), checked against the vocabulary; the element that writes `data-slot="x"` must also write the class `nz-x`. The SSR suite and the conformance tests already assert rendered DOM stays inside the vocabulary |
| attribute `group`, `values`, `meaning`  | `contracts/vocabulary.json`; a `"values": null` entry takes the manifest's `variants` under the camelCase prop (§8.3 rule 5)                                                                                                                                                                                                                                                                               |
| hooks, tokens, runtime, classes, layers | the built `dist/css/<name>.css`, parsed with Lightning CSS. Selectors come out flattened when the file is re-printed with targets below native nesting (`{ chrome: 100 << 16 }`) and `minify: false`                                                                                                                                                                                                       |
| hook `description`                      | a `/** … */` doc comment directly above the first declaration that reads the hook in `src/<name>/<name>.css` (Lightning CSS drops comments); a plain `/* … */` comment is a maintainer's note and is never published                                                                                                                                                                                       |

Rules the generator must enforce (fail with the file and the name, as `nz gen` does):

- Every read of a hook has the same fallback. All 95 week 2 hooks satisfy this.
- Every token a stylesheet reads exists in `@nizivo/tokens/dist/contract.json`, and every `data-*`
  name a slot lists exists in the vocabulary. The emitted-CSS check already guarantees both today; the
  generator re-checks rather than trusts.
- `@default` is often inline, after the text of a one-line comment (`32 / 40 / 48 px. @default 'md'`).
  TypeScript's JSDoc parser reads that as plain text, so find the tag there too and keep it out of
  `description`.
- Literal `values` follow the order written in the declaration that defines the union (the alias;
  the interface's members for `keyof ButtonVariantMap`; the tuple for `(typeof SIDES)[number]`),
  never the checker's union order, which depends on type creation order.
- On an optional member, a trailing `| undefined` is dropped (`open?: boolean | undefined` →
  `"boolean"`).
- Each entry's `.d.ts` exports the same names as its `src` barrel; otherwise `dist` is stale and
  the generator stops ("rebuild @nizivo/react") instead of writing a stale contract.
- A component's root slot is its §8.2 name: the component name for a `Root` part (`select`), else
  the kebab-case export (`select-trigger`, `grid-item`). A slot has one `renderedBy`; every
  `interactive` and `stateIndicator` slot of the manifest is rendered; every `"values": null`
  attribute has the manifest `variants` it reads.

## `ReactApiFile`

| Field       | Shape                                                                                            |
| ----------- | ------------------------------------------------------------------------------------------------ |
| `$comment`  | `"generated by nz api; do not edit"`                                                             |
| `version`   | `1`                                                                                              |
| `package`   | `"@nizivo/react"`                                                                                |
| `entry`     | the exports key: `"."`, `"./alert"`, `"./unstable/<name>"`                                       |
| `component` | `ComponentInfo`, from `component.json`; absent without a manifest                                |
| `exports`   | every runtime and type export, sorted by `name`                                                  |
| `slots`     | every element rendered with a `data-slot`, sorted by `slot`; `[]` when the entry renders nothing |

`ComponentInfo`: `name`, `status`, `tier`, `engine` (tier `engine` only), `overlay` (`true` or
absent), `stylesheet` (the `./css/<name>.css` key, absent without one), `cssDeps` (sorted) and
`variants` (keys sorted, values in manifest order).

### Exports

Every export has `name`, `kind` and `import`, the line a consumer writes, with no semicolon:
`import { Alert } from '@nizivo/react/alert'`, or `import type { … }` for a type. Most also have
`description` and `deprecated` (the `@deprecated` text, or `true` when the tag has none).

| `kind`      | What                                                      | Extra fields                                                                                                    |
| ----------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `component` | a standalone component: `Alert`, `AlertDismiss`, `Button` | the `ComponentDoc` fields (below)                                                                               |
| `namespace` | a compound's namespace object: `Card`, `Select`           | `parts`: one `PartDoc` per manifest part, in manifest order                                                     |
| `part`      | a compound part's flat name: `CardRoot`                   | `partOf`: `"Card.Root"`. Documented once, in the namespace's `parts`                                            |
| `hook`      | a React hook (`use*`)                                     | `client`, `signatures`, `source`                                                                                |
| `function`  | any other function: `stateAttrs`, `mergeProps`            | `client`, `signatures`, `source`                                                                                |
| `constant`  | a non-function value: `STATE_ATTR_NAMES`                  | `client`, `type`, `source`                                                                                      |
| `type`      | an interface or type alias                                | `declaration`, `typeParameters`, `text` (alias), `values`, `extends`, `members`, `propsOf`, `stateOf`, `source` |

An export documented in another entry's file is a `ReexportedExport`: only `name`, `kind`, `import`
(from this entry) and `definedIn` (the entry that documents it). Every export in `index.json` is
one, and so is a type an entry re-exports from another public entry (`OpenReason` in
`select.json`). `definedIn` is the only field that tells the two shapes apart; every other export
has none.

A props interface (`AlertProps`) and a render-state interface (`AlertState`) are documented on
their component, so their type export has `propsOf` or `stateOf` instead of `members`. Every other
interface (labels such as `AlertDismissLabels`, augmentation maps such as `ButtonVariantMap`) lists
its `members`.

**`ComponentDoc`** (a `component` export, and each `PartDoc`, which adds `name`, the member name
such as `"Root"`, and `flatName`, the flat export such as `"CardRoot"`):

| Field       | Shape                                                                                                                                                                                                     |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `client`    | `true` when the declaring module is a `'use client'` leaf (a client reference under RSC); `false` when it is server-safe. Per export, not per file: Alert is `false`, AlertDismiss `true`                 |
| `propsType` | the exported props interface: `"AlertProps"`                                                                                                                                                              |
| `props`     | `MemberDoc[]`, sorted by `name`: the interface's own members, plus those of any base declared in `@nizivo/react` (marked `inheritedFrom`)                                                                 |
| `inherits`  | `InheritedProps[]`: one per React DOM base, summarised instead of hundreds of rows                                                                                                                        |
| `render`    | present when there is a `render` prop: `stateType` (absent for `Record<string, never>`) and `state`, the fields of the state type, sorted                                                                 |
| `slot`      | the root element's `data-slot` (`"alert"`; `Card.Root` is `"card"`; `Select.Root` is `"select"`); absent when the component renders no element of its own (`Dialog.Root`, `Tooltip.Root`, `NizivoConfig`) |
| `source`    | `"packages/react/src/alert/alert.tsx"`                                                                                                                                                                    |

**`MemberDoc`** (props, state fields, interface members): `name`, `type` (as written), `values`
(literal members as JSON values, when the type resolves to literals only), `required`, `default`
(the `@default` text, verbatim: `"'info'"`), `description`, `deprecated`, `inheritedFrom`.

**`InheritedProps`**: `text` (the base as written: `Omit<ComponentPropsWithRef<"div">, "title">`),
`base` (without `Omit` and `Partial`), `element` (`"div"` for a `ComponentProps*` base), `omitted`
(keys removed with `Omit`, sorted) and `overridden` (own props that redeclare a name the base still
provides, sorted: Alert's `role`).

**`SignatureDoc`**: `text` (the declaration without `export declare` and the semicolon),
`parameters` (`name`, `type`, `optional`, `rest` for a rest parameter, `description` from
`@param`; positional) and `returns` (`type`, `description` from `@returns`).

### Slots

| Field            | Shape                                                                                                                                                                                                                                                                  |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `slot`           | the `data-slot` value; the class is `nz-<slot>`                                                                                                                                                                                                                        |
| `renderedBy`     | the export or part that renders it: `"Alert"`, `"Card.Root"`                                                                                                                                                                                                           |
| `part`           | `true` for the root of an export or part (its `slot`); `false` for an inner element CSS can target but that takes no `render` (`alert-title`, §8.2). Whether a root takes `render` is its component's `render` field: `Select.Root` and the engine-owned popups do not |
| `interactive`    | listed in the manifest's `interactive` (it gets the nz.base focus outline, §8.5)                                                                                                                                                                                       |
| `focusTarget`    | interactive slots only: `self`, `engine`, `nested-input` or `within`                                                                                                                                                                                                   |
| `stateIndicator` | the manifest's `stateIndicator` entries for this slot, in manifest order: `{ "state"?, "paint" }` (what `nz.base` paints in forced-colours mode, §8.5, §15.1); `[]` for most slots                                                                                     |
| `attributes`     | `DataAttributeDoc[]`: every `data-*` the element can carry, `data-slot` excluded, sorted by `name`                                                                                                                                                                     |

`DataAttributeDoc`: `name`, `group` (`state`, `presentational`, `local` or `scope`, the vocabulary
group), `presence` (`true` for a presence attribute, which has no `values`), `values`, `prop` (the
prop it mirrors: present when the rendering component's props type, DOM props included, has the
attribute's camelCase name: `data-full-width` ← `fullWidth`, Button's `data-disabled` ←
`disabled`; `data-span-sm` has none, because GridItem sets it from `span`'s `sm` key; nor has an
attribute with a value the prop's literal type does not take, such as `data-side` on Select.Popup and
Tooltip.Popup, which is the resolved physical side while `side` takes logical values) and `meaning`
(the vocabulary's).

## `CssApiFile`

| Field       | Shape                                                                                                                  |
| ----------- | ---------------------------------------------------------------------------------------------------------------------- |
| `entry`     | `"./css/alert.css"`                                                                                                    |
| `component` | the manifest `name`; absent for a shared file (`base.css`)                                                             |
| `layers`    | the layers the file writes into, in file order: `["nz.components"]`; `base.css` has `["nz.base", "nz.utilities"]`      |
| `hooks`     | `CssHookDoc[]`, sorted by `name`                                                                                       |
| `tokens`    | every `--nz-*` token read anywhere in the file, sorted; hooks, `--_nz-*` privates and runtime variables are not tokens |
| `runtime`   | the runtime variables read (`--nz-trigger-width`, §8.3), sorted                                                        |
| `classes`   | every `nz-*` class the file selects, sorted (class names are semver'd, §5.4)                                           |

Plus `$comment`, `version` and `package`, as in `ReactApiFile`.

**`CssHookDoc`**: `name`, `description` (from a `/** … */` doc comment in the source, when there is one), `fallback`
and `reads` (every declaration that reads it, sorted by `selector`, then `property`).

**`CssFallback`**, by `kind`:

| `kind`       | Written as                | Fields                                                                                    |
| ------------ | ------------------------- | ----------------------------------------------------------------------------------------- |
| `token`      | `var(--nz-space-3)`       | `name`                                                                                    |
| `private`    | `var(--_nz-alert-bg)`     | `name`, `values`: one `PrivateValue` per declaration of the private, sorted by `selector` |
| `hook`       | `var(--nz-old-name, …)`   | `name`: a deprecated hook kept as an alias for one minor (§8.4 rule 4)                    |
| `literal`    | `8.75rem`, `cover`, `1em` | `value`                                                                                   |
| `expression` | anything else (`calc(…)`) | `value`, `tokens`                                                                         |

Week 2 has 64 token, 40 private and 5 literal reads (`--nz-empty-state-media-size`, `--nz-image-fit`,
`--nz-skeleton-height`).

**`PrivateValue`**: `selector`, `conditions`, `value` (as Lightning CSS prints it) and `when`, the
`data-*` conditions on the selector's subject (`{ "data-tone": "critical" }`; `""` for a presence
attribute; `{}` for the rest rule). A docs table can show "Default: `--nz-bg-info-subtle`;
critical: `--nz-bg-critical-subtle`" from it.

**`CssHookRead`**: `selector` (nesting resolved, as Lightning CSS prints it unminified, with
attribute values in double quotes: `.nz-alert-dismiss:hover`), `conditions` (enclosing conditional
at-rules, outermost first, without layers: `["@media (hover: hover)"]`), `property`, and `slot`
(the last `nz-*` class of the selector's subject compound, minus `nz-`). A rule with a selector
list gives one read per selector, and one `PrivateValue` per selector, each with its own `when`.

## For the renderer

- Read files with `import type { ReactApiFile, CssApiFile } from '@nizivo/tooling/api/schema'`
  (or a relative path) and plain `JSON.parse`; there is no runtime validator.
- Group a component page by `exports`: a `namespace` with its `parts`, then `component`s, then
  `hook`s and `function`s; list `type` exports with `members` in a types section, and skip those
  with `propsOf` or `stateOf`, which their component already shows.
- Show inherited DOM props as one row from `inherits` ("…and every `<div>` attribute except
  `title`"), linking `element` to its attribute list.
- `client: true` deserves a visible marker: it is the one place a server page pays client JS.
- The hook table joins `reads[].slot` with the React file's `slots` for the part name, and a token's
  type with `@nizivo/tokens/contract.json`.
- `version` is `1`. Refuse any other value rather than render it wrong.
