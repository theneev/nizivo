**Shared code this week** (the overlay family, §12.2):

- `_internal/modal.client.tsx`: the modal leaves' nesting context and focus-on-open rule, moved out of Dialog's leaf, so a Drawer opened from a Dialog (or the other way round) draws no second scrim and marks its parent `data-nested-open`. Dialog's behaviour is unchanged (its specs pass as before).
- `InitialFocus` moved from the Dialog adapter to `popup.client.tsx`, for Dialog, Drawer and Popover.
- **A fix for every overlay of the family: outside press inside a Dialog** ([D-bn](../../docs/ARCHITECTURE.md#234-builder-defaults-2026-10-14)). Building O-12 showed that a Select, Menu or nested Dialog opened inside a Dialog did not close on a press outside it, since week 4: React Aria's `useInteractOutside` ignores every press inside an element marked top-layer, and the family's nested-portal containers carry that mark (D-af). Confirmed on the unchanged week 12 code before the fix. The new completion `outside-press` (`outside-press.client.tsx`) closes the topmost popup of the family on such a press, never inside `data-nz-top-layer` (the toast region) or on a tooltip, and never an alertdialog. `OverlayEngine.completes` now lists five completions.
- `nz api` follows an adapter's `export { … } from` re-exports (`packages/tooling/api/slots.ts`), so the Drawer's record reads the Dialog adapter's state attributes.

## Deviations from Figma and the plan (kept on purpose)

- **Drawer close:** an IconButton, not Figma's bare 20 px icon (figma/07 §6.2 asked for this; the same as the Dialog's).
- **Drawer motion:** `duration/slow` + `easing/enter` in, `duration/base` + `easing/exit` out (figma/07 §6.5's proposal), not the spring pair §13.3 gives other overlays: its 3 % overshoot would open a gap between the drawer and the viewport edge.
- **Drawer under reduced motion:** a component rule reads `prefers-reduced-motion` and `[data-nz-motion="reduce"]` and drops the slide (figma/08 §8.3: "use opacity only"). §13.2 rule 3 now names two such rules (Button's pending label and this one).
- **Drawer `side`:** no `top`, `size` or `modal={false}` (§12.3 lists `top` and non-modal push; neither is needed by the shell's "More" sheet, and O-23 is v1.0).
- **Drawer on a narrow viewport:** a 3rem strip of scrim stays beside (or above) it, so there is always somewhere to press; Figma draws only the desktop width.
- **Popover:** every visual value is a builder choice, as Figma draws none: 16 px padding, a 22.5rem maximum width, Heading/H4 titles, a 32 px close in the corner.

## For the maintainer

1. **Popover and Drawer are over §17.1's figures.** §17.1's "Popover 29.4 / 32" and "Sheet 26.3 / 29" are r3's React-Aria-only measurements; Nizivo's subpaths measure 35.0 and 31.7 KiB (Dialog went the same way: r3 28.1, Nizivo 31.4, raised to 32 by M17). They are gated provisionally at measured + 10 % (39 and 35 KiB) as new entries; `PLAN_LIMITS_KIB` and every existing limit are unchanged (D-bo). Options: (a) raise §17.1 to 39 and 35 KiB, a labelled raise; (b) tie Drawer to Dialog's 32 KiB (it is Dialog's engine plus 68 B; 270 B headroom) and Popover to 36 KiB; (c) hold the two subpaths out of the exports map until they fit (D-bc's route for AreaChart). **Recommendation: (a)**, as M17 did for Dialog: the gap is Nizivo's layer, which r3 did not measure.
2. **The dashboard set and Popover.** §17.1 defines the set as Dialog, Popover, Menu, Select, Tabs, Tooltip; W5 measured it without Popover, which did not exist. It now measures 77,740 B, 84 B under 76 KiB, without Popover; with Popover it grows by about 800 B (esbuild with the size method's settings: 77,515 → 78,316 B), so about 78.5 KB on size-limit's scale, roughly 720 B over 76 KiB. Options: (a) add Popover and raise the set's limit to measured + 10 % (labelled); (b) keep the W5 definition and record that the set omits Popover. **Recommendation: (a)**, so the set measures what §17.1 says it does; with 84 B left, the next change to any overlay goes over either way.
3. **The outside-press fix touches shipped components** (D-bn). Since week 4, a Select, Menu or nested Dialog inside a Dialog stayed open on a press outside it (Escape worked). The fix adds 225 to 266 B to each overlay subpath. Options: (a) keep it (built; the changeset says "fixed"); (b) drop the top-layer mark from the nested containers instead (smaller, but a Tooltip inside a Dialog becomes inert, the week 4 problem); (c) leave it as a known limitation. **Recommendation: (a).**
4. **Popover modality.** It is React Aria's modal popover, as §12.3 says ("engine default modal"): the page is inert and does not scroll while it is open, and Tab stays inside. A non-modal popover (Tab leaves and closes it; no lock) is closer to an account or notifications menu on a dashboard. Options: (a) keep modal for v0.2; (b) add `modal={false}` (`isNonModal`) now, with its own conformance case. **Recommendation: (a)**; revisit when the TopBar's account and notifications popovers are built.
5. **The Drawer's open motion is not the spring** (D-bl): the spring pair's 3 % overshoot would open a gap at the edge. Options: (a) keep `duration/slow` + `easing/enter` (figma/07 §6.5's proposal); (b) `easing/spring-soft` (no overshoot, 702 ms); (c) ask design. **Recommendation: (a)**, and ask design (Dayitava) to confirm.
6. **The Drawer's reduced-motion rule** is a second component rule that reads the preference (§13.2 rule 3; Button's pending label was the first). Options: (a) keep it; (b) a code-owned token for the travel (`100%` → `0`), so the rule becomes a token swap again. **Recommendation: (a)**: one consumer does not justify a token.
7. **Design asks** (for Dayitava): a Popover component (Figma has none: padding, width, title style and arrow are builder choices, D-bk); the Drawer's `start`, `bottom` and narrow-viewport renders; the "More" sheet's contents (handoff Q35), which AppShell needs.
