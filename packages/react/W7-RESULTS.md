## What week 7 built

- **M25, 16 px text fields under a coarse pointer** (§15.1, §9.5). Each of Input, Textarea, NativeSelect and the Select trigger gets a private font variable (`--_nz-input-font`, `--_nz-textarea-font`, `--_nz-native-select-font`, `--_nz-select-font`) that defaults to the current style and switches inside a nested `@media (pointer: coarse)` block to the 16 px style of the same weight: Body/L for Input and Textarea, Label/L for both selects. No token was added (`--nz-font-body-l` and `--nz-font-label-l` exist), and `@nizivo/tokens/custom-media.css` has no coarse-pointer query, so the raw `(pointer: coarse)` is used, as base.css's hit-target rule does. The public `--nz-*-font` hooks are still read once, with the private as their fallback: a page that sets one owns the iOS zoom. Input, NativeSelect and Select keep 32/40/48 px; a Textarea row grows from 21 px to Body/L's 25.6 px line (Mobile Safari 17.5 lays it as 25 px). The prefix, suffix and placeholders inherit the size.
- **M26, Tabs direction** (§16.4). `Tabs.Root` takes `dir?: 'ltr' | 'rtl'` (before: a passthrough `string`, so `dir="auto"` no longer typechecks), rendered as its `dir` attribute; the arrow keys follow it, else the nearest enclosing `Tabs.Root`'s `dir`, else the `NizivoConfig` locale's direction. React Aria's only direction input is the locale given to `I18nProvider`, so the tab list alone gets a carrier locale: the scope's own when its direction already matches (every render without `dir` is unchanged), else `ar` or `en`. Each tab's content and every panel get the scope locale back. `NizivoConfig` keeps no direction key.
- **M27, a minimum size for bare triggers** (§15.1). A `Dialog.Trigger` or `Tooltip.Trigger` with no `render` (its own `<button>`) adds `nz-hit-target`, the class every standalone pressable uses for the 44 px coarse-pointer hit area, and `.nz-dialog-trigger.nz-hit-target` / `.nz-tooltip-trigger.nz-hit-target { min-inline-size: 1.5rem; min-block-size: 1.5rem }` gives it the 24 × 24 px of WCAG 2.2 2.5.8. `.nz-hit-target` does nothing on a fine pointer, so the minimum needed a rule of its own. A composed Button or IconButton also matches the rule, but at 32 px or more it changes nothing; an element passed through `render` gets neither.
- **D-aa** (§23.4): investigated, nothing changed in the repo (section "D-aa").

## D-aa

The maintainer's condition (2026-10-16): "If 'Add client-import-free entries now' would not cause any issues, and not a bad DX, then sure". The builder tried to get the saving with no new import path first. Measured in a clone of 00266d6 on the Next fixture (gzip -9 sum of a page's client chunks minus `/button-only`):

| Page                         | Turbopack prod | webpack prod | `next dev` |
| ---------------------------- | -------------: | -----------: | ---------: |
| `/icon-button` (tooltip off) |      +20,805 B |            0 |  +62,124 B |
| `/icon-button-tooltip`       |      +20,805 B |    +21,428 B |  +62,124 B |
| `/field-zero-js`             |       +3,035 B |            0 |   +7,800 B |

A build with no leaf imports at all makes `/icon-button` and `/field-zero-js` equal `/button-only`, so the whole difference is the client leaf.

- **Design A**, a server shell that loads the leaf with `lazy(() => import())`: Turbopack still ships the chain (+20,875 B prod, +62,534 B dev). Turbopack ships every client module the server graph reaches, static or dynamic.
- **Design B**, a thin client leaf that lazy-loads the tooltip chain inside its own `<Suspense>`: Turbopack prod `/icon-button` +2,191 B, dev +5,639 B; tooltip pages pay about +500 B (+583 Turbopack, +487 webpack). It fails the condition three ways: `renderToString` emits a `<!--$!-->` client-render boundary ("Switched to client rendering"; `test/ssr/icon-button.test.tsx` fails); a client navigation to a tooltip page replaces the button's DOM node (at 0 and 150 ms latency), detaching a ref and losing focus; and handlers attach later on tooltip pages (median of 9: +15 ms Turbopack, +12 ms webpack on localhost; 709 vs 650 ms and 716 vs 645 ms at 150 ms latency). First load under Next streaming keeps the node. Field cannot use it: its controls read FieldScope's context on their first render.
- **What works:** a second export in a module that imports no client leaf (`IconButtonStatic`, `FieldStatic`) ships nothing extra in all three modes, through the existing subpath and the barrel. That is new public API, against M13's one export per subpath, or two new subpaths; either needs the shells' helpers (`iconButtonElement`; Field's `describedBy`, `fieldControlProps`, `fieldRootProps`, `fieldState`) moved into leaf-free modules first, and `<IconButton tooltip={false}>` itself would still ship the chain under Turbopack. **The maintainer's call;** nothing was added.
- The runner's `closure()` (`fixtures/runner/spec.ts`) follows only static import edges, so a dynamic `import()` in a client module would be reported as "unexpected client modules".

## Week 7 review

Two reviewers filed 13 findings: 9 fixed, 2 answered in the docs with the decision left to their owners, 1 resolved before the fixes started, and 1 rejected with the reason.

- **R1-TABS-NESTED (fixed).** A `Tabs.Root` without `dir` reset the direction context, so a strip nested in the panel of a `dir="rtl"` root was laid out right to left (CSS inherits the attribute) while its arrows followed the `en-US` scope: ArrowLeft went to the previous tab. A root without `dir` now takes the nearest enclosing root's (`dom.dir ?? use(Dir)`) and renders no attribute of its own. New cases: a browser case (the inner strip's computed direction is `rtl` and its keys match, in Chromium, Firefox and WebKit; it fails with the fix reverted) and an SSR case (the inner root has no `dir`, its list resolves `ar rtl`, and its own `dir="ltr"` still wins).
- **R1-TABS-LABEL-LOCALE (fixed).** The carrier wrapped the whole tab list, so a consumer's React Aria hook in a tab label read `ar` under `en-US` with `dir="rtl"` (a number formatter would print Arabic digits). Each tab's content is now wrapped in `EngineLocale`, always rendered, so a change of `dir` never remounts a label. A tab's `textValue` falls back to `''` because its children are now an element; it is read only by type-ahead and filtering, which tabs do not have. The SSR suite reads the carrier through a tab's `render` element (which sits inside the carrier, around the content) and the content's locale separately; both new cases fail with the fix reverted.
- **R1-TRIGGER-INLINE-HIT and R1-TRIGGER-INLINE-LINE (docs; the decision stays with the maintainer and Dayitava).** Inside running text a bare trigger's 44 px coarse-pointer hit area reaches into the lines above and below and takes taps from a link there, and its 24 px minimum makes the line taller (84 → 87 px for a four-line paragraph). WCAG 2.2 2.5.8 exempts targets in a sentence. The Dialog and Tooltip pages now say to render your own element through `render` for a trigger inside a sentence; it carries neither. An opt-out attribute would touch the vocabulary, so it was not added.
- **R1-TRIGGER-SELECTOR (fixed):** the dialog.css and tooltip.css comments now say the rule also matches a composed Button or IconButton (harmless at their sizes; it floors a custom height below 24 px). No code change.
- **R1-SPEC-COMMENT (fixed):** the tabs browser spec's header no longer mentions a `NizivoConfig` `dir`.
- **F1 (fixed):** the Tabs page's ArrowRight/ArrowLeft `action` carried backticks, which the keyboard table shows as plain text, so the docs smoke check failed ("raw Markdown"). The action text has none now (and no `: `, which the front matter's YAML would read as a mapping).
- **F2 (fixed):** this file did not exist although ARCHITECTURE.md cited it.
- **F3 (resolved before the fixes started):** the two reviewer probe files under `packages/react/test/zz-rev1/` were already gone; `git status --untracked-files=all` listed only the four new `-touch.json` floor results.
- **F4 (fixed):** the Vite and Astro byte tables are re-synced with the recorded results JSON, after the fixtures were re-recorded on the fixed tree (section "Fixtures").
- **F5 (fixed):** the integration's `--rebase` raised six non-§17.1 budgets, five of which still held (`own: dialog/dialog.client` 1,309 B of 1.4 KiB, `css/dialog.css` 944 B of 1 KiB, `css/input.css` 844 B of 0.9 KiB, `css/tooltip.css` 581 B of 0.6 KiB, `styles.css` 14,971 B of 16 KiB). Those five are back at their old limits; the one that had to move (`own: _engines/react-aria/tabs.client`, 769 B over 0.7 KiB) is raised to 0.9 KiB in its own labelled size commit, placed before the Tabs commit so every commit passes `pnpm size`.
- **F6 (fixed):** ARCHITECTURE.md §15.1's Target size row no longer says both "visible sizes never change" and "heights stay … (the one visible size change)": hit areas never change the visible size, and the coarse-pointer text is the one exception (Textarea rows grow to 25.6 px).
- **F7 (rejected, note extended).** The finding says the bare-trigger minimum yields a 24 px border box only under a `border-box` reset. It does not: the rule matches a `<button>`, which every engine's user-agent stylesheet makes `border-box` (measured above), or a Button or IconButton, which set it themselves. Adding `box-sizing` would change nothing. The week 5 grep note in `fixtures/floor-lane/RESULTS.md` now lists the two rules and why they are harmless.
