# `tokens.json` and the typed JS references

Date: 2026-10-15 (week 4). Plan: ARCHITECTURE.md §5.2 (the exports map), §7.1 (the pipeline),
§7.3 (the prefix), §15.4 (CSS, JS refs, Tailwind and JSON agree).

`@nizivo/tokens` ships two outputs for code that cannot read CSS custom properties, or wants types
for them:

| Export          | File                               | For                                                                            |
| --------------- | ---------------------------------- | ------------------------------------------------------------------------------ |
| `./tokens.json` | `dist/tokens.json`                 | charts, canvas, native and email renderers, design tools: literal values       |
| `.`             | `dist/index.js`, `dist/index.d.ts` | typed `var()` references for inline styles and CSS-in-JS, breakpoints, springs |

Both are written by the token build (`tz build`), by two Terrazzo plugins in `build/js.ts` on the
resolved set from `build/resolve.ts`. tsdown still compiles `src/index.ts`, an empty placeholder, as
the first step of `pnpm build`; the `js-refs` plugin then replaces `dist/index.js` and
`dist/index.d.ts`. Both outputs are pinned by byte goldens (`test/golden/`).

## How values are resolved

Every value is computed from the declaration `tokens.css` holds for the token, so the JSON cannot
disagree with the CSS: `var(--nz-…)` is replaced by that variable's value in the same context,
`light-dark(a, b)` by the theme's side, and an outside hook such as `var(--font-geist-sans, "Geist")`
by its fallback. The motion and viewport contexts apply the scoped blocks over `:root`, as the cascade
does. `test/js.test.ts` re-reads the built `tokens.css` with a separate small evaluator and checks
every value in every context (2,338 comparisons).

## `tokens.json`

### Why a flat shape, not DTCG

The file is flat: one object per token, keyed by the DTCG token id (`color.bg.surface`), the same id
`contract.json` names in each variable's `token` field. A DTCG-shaped file (nested groups, `$value`)
was rejected for three reasons:

1. **Its consumers want literals.** A chart, a canvas or an email renderer needs `#1a573a`, not
   `{color.p.green.800}`. A DTCG `$value` keeps aliases, so every consumer would re-implement the
   resolution the build already does.
2. **Several values exist only in CSS.** The dark elevation shadows (black at min(0.6, 6 × alpha),
   with the ring), the `color-mix()` focus halo, the font stacks with their `next/font` hook and the
   tracking in `em` are computed by `build/css.ts`. DTCG has no place for a value per mode, and its
   `$value` for these tokens would contradict `tokens.css`.
3. **Lookups are by id.** A flat object is one property access; nested groups make `color.bg` a
   group and a token at the same time in tools that walk the tree.

The source of truth in DTCG form remains `src/**` with `src/nizivo.resolver.json` (DTCG 2025.10).

### Top level

```jsonc
{
  "$comment": "Generated by the @nizivo/tokens build. Do not edit. …",
  "format": 1, // the version of this shape; see "Compatibility" below
  "package": "@nizivo/tokens",
  "prefix": "nz", // published packages always use nz (§7.3)
  "modifiers": {
    "theme": { "contexts": ["light", "dark"], "default": "light" },
    "motion": { "contexts": ["default", "reduced"], "default": "default" },
    "viewport": { "contexts": ["mobile", "tablet", "desktop"], "default": "mobile" },
  },
  "tokens": { "<token id>": { … } }, // 237 tokens, sorted by id (numeric-aware)
}
```

### A token

```jsonc
"color.text.critical": {
  "type": "color",                     // the DTCG $type
  "cssVariable": "--nz-text-critical", // null for breakpoint.* and layout.viewport (never variables, §7.2)
  "public": true,                      // false for the color.p.* primitives and layout.viewport
  "value": "#b93a23",                  // the default context: light, default motion, mobile
  "provenance": "figma",               // of the default value
  "aliasOf": "color.p.red.600",        // the token it aliases in that context, when it is an alias
  "modes": {                           // only the contexts whose entry differs from the default
    "theme": {
      "dark": { "value": "#e47962", "provenance": "override", "aliasOf": "color.p.red.400" }
    }
  },
  "figma": { "name": "text/critical", "variableId": "VariableID:737:146" }
}
```

| Field         | Always | Meaning                                                                                                                       |
| ------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------- |
| `type`        | yes    | `color`, `dimension`, `duration`, `number`, `string`, `cubicBezier`, `shadow`, `fontFamily` or `typography`                   |
| `cssVariable` | yes    | the custom property `tokens.css` declares, or `null`                                                                          |
| `public`      | yes    | part of the public API; matches `contract.json`. Breakpoints are public (as custom media)                                     |
| `value`       | yes    | the literal value in the default context (formats below)                                                                      |
| `provenance`  | yes    | `figma`, `code-owned`, `override` or `proposal` (below)                                                                       |
| `aliasOf`     | no     | the aliased token id in the default context                                                                                   |
| `modes`       | no     | `{ <modifier>: { <context>: { value, provenance, aliasOf? } } }`; one modifier at most per token (the resolver is orthogonal) |
| `parts`       | no     | typography only: the part variables, keyed like the value (`letterSpacing` is `--nz-tracking-*`)                              |
| `customMedia` | no     | breakpoints only: `--nz-sm`, `--nz-lg`                                                                                        |
| `status`      | no     | `provisional` (outside semver; today `breakpoint.lg`)                                                                         |
| `deprecated`  | no     | `true` or a message, from the source's `$deprecated`                                                                          |
| `description` | no     | the source's `$description`                                                                                                   |
| `figma`       | no     | the Figma identity: `name`, and `variableId` or `styleId` when the export has one (effect styles have none)                   |

**Reading a value in a context.** A context that is not listed under `modes` has the default entry:

```ts
import data from '@nizivo/tokens/tokens.json' with { type: 'json' };
import type { TokensJson } from '@nizivo/tokens';

const tokens = data as TokensJson; // a JSON import widens string literals, so cast it
const valueIn = (id: keyof TokensJson['tokens'], modifier: string, context: string) => {
  const token = tokens.tokens[id];
  return (token.modes?.[modifier]?.[context] ?? token).value;
};
valueIn('color.chart.primary', 'theme', 'dark');
```

**What the contexts mean.** `theme.dark` is a `[data-nz-theme="dark"]` scope (or `system` on a dark
OS); an inverse surface (`data-nz-scheme="inverse"`) takes the other theme. `motion.reduced` is
`prefers-reduced-motion: reduce` or `[data-nz-motion="reduce"]`. `viewport.tablet` is
`width >= 40rem` and `viewport.desktop` is `width >= 80rem` (provisional).

### Provenance

Read per context from the markers in the token sources (§7.6, §15.4), strongest first:

| Provenance   | Marker                               | Meaning                                                                                                             |
| ------------ | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| `override`   | `$extensions["app.nizivo.override"]` | a Figma variable re-pointed for contrast or the ladder; it expires (CONTRAST.md)                                    |
| `proposal`   | `$extensions["app.nizivo.proposal"]` | a variable or primitive Figma does not have yet; it expires                                                         |
| `code-owned` | none, or `app.nizivo.derived`        | code-owned by nature (breakpoints, z-index, families, focus), or generated from Figma (the spring `linear()` pairs) |
| `figma`      | `$extensions["dev.nizivo.figma"]`    | Figma's value, as the normaliser wrote it                                                                           |

An override can apply to one theme only: `color.text.critical` is `figma` in light and `override`
in dark. Today: 194 tokens are `figma`, 20 `code-owned`, 19 `proposal` and 4 `override` in the default
context; the 14 overrides of CONTRAST.md are the light ones plus those under `modes.theme.dark`.

### Value formats

Values are the CSS text `tokens.css` computes, with every `var()` and `light-dark()` resolved:

| Type          | Example                                                                                                                     | Notes                                                                                                     |
| ------------- | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `color`       | `"#1a573a"`, `"rgb(24 27 25 / 0.32)"`, `"transparent"`                                                                      | hex when opaque                                                                                           |
| `dimension`   | `"0.75rem"`, `"1px"`                                                                                                        | rem from px ÷ 16; border widths stay px (§7.2)                                                            |
| `duration`    | `"150ms"`                                                                                                                   |                                                                                                           |
| `number`      | `"12"`, `"0.96"`                                                                                                            | a string, as in CSS; `Number()` it                                                                        |
| `cubicBezier` | `"cubic-bezier(0.2, 0, 0, 1)"`, `"linear"`                                                                                  |                                                                                                           |
| `string`      | `"linear(0, 0.007 1.5%, …)"`, `"color-mix(in oklab, #2e8358 28%, transparent)"`                                             | the spring easings, focus halo and ring, the inverse scheme                                               |
| `shadow`      | `"0 0 0 1px transparent, 0 4px 8px 0 rgb(16 19 17 / 0.05)"`                                                                 | the elevation ring and highlight included, per theme                                                      |
| `fontFamily`  | `"\"Geist\", ui-sans-serif, system-ui, sans-serif"`                                                                         | the `next/font` hook resolves to its fallback                                                             |
| `typography`  | `{ "font": "500 0.875rem/1.4 \"Geist\", …", "fontFamily", "fontSize", "fontWeight", "lineHeight", "letterSpacing": "0em" }` | `font` is the shorthand (`ctx.font` accepts it); `letterSpacing` is the tracking the shorthand leaves out |

### Compatibility

`format` is 1. Adding a field, a token or a context is not a format change. Removing or renaming a
field, or changing a value's format, bumps `format`. A removed or renamed public token is a breaking
change of the package either way (§7.1).

## The `.` entry: typed `var()` references

```ts
import { color, space, font, typography, breakpoints, springs } from '@nizivo/tokens';

<div style={{ background: color.bgSurface, padding: space[4], font: font.labelM }} />;
// color.bgSurface: 'var(--nz-bg-surface)', typed as that literal
matchMedia(breakpoints.sm).matches; // '(width >= 40rem)'
```

**Groups and keys.** One named export per token group, so a bundler drops the groups a page does not
import. The group is the first segment of the token id, camel-cased (`border-width` → `borderWidth`);
the key is the rest, camel-cased: `color.bg.surface` → `color.bgSurface`, `font.label.m-strong` →
`font.labelMStrong`, `size.control-md` → `size.controlMd`. A digit-dash-digit becomes a dot, so the
key reads like Figma: `space.0-5` → `space[0.5]`, `space.1-5` → `space[1.5]`. Keys come from token
ids, never from variable names, so `NZ_TOKEN_PREFIX` changes the values only.

| Export                                                                                                                                                                                                                   | Holds                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| `borderWidth`, `color`, `distance`, `duration`, `easing`, `elevation`, `focus`, `font`, `grid`, `layout`, `magnetic`, `radius`, `scale`, `scheme`, `section`, `size`, `space`, `stagger`, `surface`, `tilt`, `type`, `z` | `var()` references to every public token with a variable (no primitives, no `--nz-css-version`)                                    |
| `typography`                                                                                                                                                                                                             | per text style, its parts: `{ fontFamily, fontSize, fontWeight, lineHeight, letterSpacing }` (`font.labelM` is the shorthand)      |
| `breakpoints`                                                                                                                                                                                                            | `{ sm, lg }`: the media queries of `custom-media.css`, for `matchMedia()`; `lg` is provisional                                     |
| `springs`                                                                                                                                                                                                                | `{ spring, springSoft }`: Figma's `spring(mass, stiffness, damping, velocity)` behind `easing.spring*`, for JS animation libraries |

Types only, no runtime: `CssVariable` (every public token variable, for `style.setProperty()`),
`TokenId` (every id in `tokens.json`) and the `tokens.json` shape (`TokensJson`, `TokenEntry`,
`TokenContextValue`, `TokenTypographyValue`, `TokenProvenance`). Each reference's doc comment shows
its values per context, so an editor hover answers "what is this in dark?".

**Cost.** The module is string and number literals only: no imports, no calls, no side effects
(`sideEffects` lists CSS only). All of it is 13.2 KB, 2.4 KB gzip; `color` alone is 0.7 KB gzip and
`typography` 0.6 KB. Unused groups are dropped; a used group ships whole.

Every `var()` it holds names a public variable `tokens.css` declares, and every public token variable
has exactly one reference (`test/js.test.ts`). A consumer file compiles against the published
`index.d.ts`, with deliberate mistakes that must fail (a primitive as `CssVariable`, an unknown key,
a write to a read-only reference, an unknown `TokenId`).
