Every Nizivo component renders its HTML on the server (an overlay's popup only while it is open). What differs is whether the browser also
downloads and runs JavaScript for it. This page says, for each component, exactly when that happens,
so a person or a coding agent can pick the right one without measuring. The rules apply to React
Server Components (the Next.js App Router); [Outside Next.js](#outside-nextjs) covers Vite and Astro.
In a client-rendered app, none of it limits you: see [In a client app](#in-a-client-app).

Charts (`@nizivo/charts`) use the same kinds: see [Charts](/docs/charts/#the-parts).

## In a client app

"Server" on these pages means a component **can** render in a Server Component with no JavaScript. It
never means server only. In a client app (a Vite or React Router single-page app, or any file with
`'use client'` in Next.js) every Nizivo component is an ordinary React component: pass `onClick`,
`onChange` and the other event handlers, refs, controlled values and state as you would to any
element, fetch on the client, and update optimistically. The one rule on this page that is about
functions, "a Server Component cannot pass `onClick`", is React's rule for every component, not
Nizivo's.

Two components are built around URLs, because navigation is their job; both also work on state:

- **Pagination** takes `getHref` for links, or `onPageChange` for client state: each page is then a
  `<button type="button">`, and choosing one calls `onPageChange(page)` with no navigation.
- **Table sorting**: `Table.SortButton` with `href` is a link; without it, it is a
  `<button type="button">` for your own `onClick`, and `sort` on its `Table.Head` sets `aria-sort`
  and the arrow.

Both demos below run on React state, with no URL and no reload.

'use client';
import { useState } from 'react';
import { Pagination } from '@nizivo/react/pagination';

export function Products() {

  const rows = products.slice((page - 1) * 3, page * 3);
  return (
    <>
      <ProductTable rows={rows} />
      <Pagination page={page} totalPages={Math.ceil(products.length / 3)} onPageChange={setPage} />
    </>
  );
}

```tsx
'use client';
import { useState } from 'react';
import { Table, type TableSort } from '@nizivo/react/table';

export function SortedProducts() {
  const [column, setColumn] = useState<'name' | 'price'>('name');
  const [direction, setDirection] = useState<TableSort>('ascending');
  const sortBy = (next: 'name' | 'price') => {
    setDirection(next === column && direction === 'ascending' ? 'descending' : 'ascending');
    setColumn(next);
  };
  // …sort `products` by column and direction into `rows`
  return (
    <Table.Root aria-label="Products">
      <Table.Header>
        <Table.Row>
          <Table.Head sort={column === 'name' ? direction : undefined}>
            <Table.SortButton onClick={() => sortBy('name')}>Product</Table.SortButton>
          </Table.Head>
          {/* the same for price */}
        </Table.Row>
      </Table.Header>
      <ProductTable rows={rows} />
    </Table.Root>
  );
}
```

## The three kinds

- **Server.** The component's module has no `'use client'` and imports no client module. Rendered by
  a Server Component and imported from its own subpath (`@nizivo/react/<name>`), it ships **no**
  client JavaScript in any Next.js build mode (Turbopack, webpack, `next dev`). 39 components.
- **Split.** A server shell plus a small client leaf that only certain props render. Without those
  props no client code runs. 8 components: Alert, Banner, Field, Form, IconButton, MobileTabBar, Sidebar and TableSelection. Alert's shell does not import
  its leaf, so an Alert without `dismiss` ships nothing in every mode. **Field's and IconButton's
  shells import their leaf**, and Turbopack and `next dev` ship every client module a page's server
  code imports, rendered or not: those two ship their leaf even when the interactive path is off.
  Their static variants exist to fix exactly that.
- **Client.** The component is a client module (a thin leaf around a native control, a React Aria
  engine part, or CountUp's animation). It always ships JavaScript, and its server HTML still works
  before hydration where the native element allows it (a checkbox toggles, a form submits; CountUp
  shows its final value). 20 components.

A **static variant** is a second export, from the same import path, that imports no client module:

- `IconButtonStatic` from `@nizivo/react/icon-button`: the IconButton's markup, classes and CSS, with
  no tooltip. `aria-label` is always required; you may also pass `aria-labelledby` pointing at visible
  text, which then names the button, with `aria-label` as the fallback. It takes no `label`, `tooltip` or
  `shortcut`; announce a shortcut with `aria-keyshortcuts` yourself.
- `FieldStatic` from `@nizivo/react/field`: the Field's anatomy (label, description, error), with no
  FieldScope. It renders no inline native validation message and no announcer, takes no `messages`
  or `validateOn`, and you wire the control: its child is always a function that receives the
  control's attributes (`id`, `name`, the flags, `aria-describedby`, `aria-invalid`) to spread on it,
  and, as a second argument, the Field's ids, `labelledBy` and `describedBy` for a control that is not
  one labelable element.

A static variant renders the same HTML as the normal component for the props they share. It is not a
cheaper copy: it drops a feature, so use it only when you do not need that feature.

## Decide in eight steps

Apply these in order; the first step that answers stops the walk.

First, the import path. Import each component from its subpath (`@nizivo/react/<name>`). The root
barrel (`@nizivo/react`) is safe only with Turbopack or `optimizePackageImports`; under plain webpack
it ships every client module in the library, whatever the page renders (see
[The barrel and webpack](/docs/getting-started/next/#the-barrel-and-webpack)). Every claim below
assumes subpath imports.

1. **Is the code a Server Component?** If the file, or any file that imports it, starts with
   `'use client'`, or the app has no Server Components (a Vite single-page app, the Pages Router, an
   Astro `client:*` island), every component you import ships its code whatever its kind. Choose by
   behaviour; steps 6 to 8 still apply, because a static variant also keeps the Tooltip code or
   FieldScope out of a client bundle when nothing else imports them.
2. **Look up the component's kind** in [the table below](#every-component).
3. **Server kind:** use it as it is. It ships nothing.
4. **Client kind:** use it when you need what it does. If the table names a static alternative and
   that alternative does the job (NativeSelect for Select, TabNav for Tabs when every view is a URL),
   prefer the alternative.
5. **Alert:** pass `dismiss` only when the alert can be dismissed. Nothing else changes what it ships.
6. **IconButton:** does a sighted user need the hover or focus text to know what the button does?
   - Yes (the usual case for an icon-only button, and Figma's rule: "Icon-only buttons have an
     aria-label and a Tooltip"): use `IconButton`. If the name can be visible text instead, use a
     `Button`, which needs no JavaScript.
   - No, because something visible already names it (a column header, a heading, a visible label next
     to it): use `IconButtonStatic` with `aria-label`.
7. **Field:** is the control a Nizivo client control (Input, Textarea, Checkbox, Switch,
   SegmentedControl, Select)?
   - Yes: use `Field`. The control ships its own client code and reads FieldScope, so the page loads
     FieldScope anyway, and `Field` adds the inline validation message and the announcer.
   - No, it is a NativeSelect or a plain native element, and you want no JavaScript: use `FieldStatic`
     with a function child that spreads its argument on the control.
8. **Count modules, not instances.** The cost is per client module per page. If the page already
   loads the Tooltip code (any `IconButton`, a `Tooltip`, a Menu whose trigger is an `IconButton`) or
   FieldScope (any client control or Select inside a `Field`), a static variant saves nothing on that
   page; use the normal component there for one behaviour throughout. `Dialog.Close` and
   `AlertDismiss` do not count: they write the IconButton markup themselves and import no tooltip.

A Server Component cannot pass a function to a client component (`onClick`, `onChange`, a function
`render`): a function cannot cross into a client module. A server part takes one from a Server
Component directly, because nothing crosses: Pagination's `getHref` and a function `renderLink`
run on the server. For a client part, use links, a `<form action={serverAction}>`, a Server Action passed to a client part that
takes one (`AlertDismiss onDismiss`), or move the interactive part into a client component.

## What it costs

Measured by the Next.js fixture (`fixtures/next`, Next 16.4.0, React 19.3.0, recorded in
`fixtures/next/results/*.json` in week 9): the gzip of every JavaScript chunk a page loads, minus the
page `/button-only` (three Buttons: 174,639 B under Turbopack, 171,889 B under webpack, 818,350 B
under `next dev`, which is unminified). Each figure is per page, whatever the number of instances.

- `/t0`, every server component of week 2 and a static Alert: 0 B in all three modes.
- `/alert-dismiss`, an Alert with `dismiss`: Turbopack +1,490 B, webpack +1,576 B, `next dev`
  +3,564 B.
- `/field-zero-js`, two Fields on the zero-JS paths: Turbopack +3,364 B, webpack 0 B, `next dev`
  +8,551 B.
- `/icon-button`, one IconButton with `tooltip={false}`: Turbopack +20,802 B, webpack 0 B,
  `next dev` +62,742 B.
- `/icon-button-tooltip`, one IconButton with its tooltip: Turbopack +20,802 B, webpack +21,444 B,
  `next dev` +62,742 B.
- `/tooltip-default-open`, one Tooltip: Turbopack +19,625 B, webpack +20,334 B, `next dev`
  +60,061 B.
- `/forms`, Input, Textarea, Checkbox and SegmentedControl in Fields, a Fieldset of two Switches
  and a RadioGroup: Turbopack +5,581 B, webpack +6,280 B, `next dev` +12,916 B.
- `/tabs`, one Tabs: Turbopack +38,812 B, webpack +38,458 B, `next dev` +109,596 B.
- `/dialog-default-open`, one Dialog: Turbopack +61,402 B, webpack +61,765 B, `next dev`
  +193,504 B.
- `/menu`, one Menu: Turbopack +61,399 B, webpack +61,199 B, `next dev` +191,452 B.
- `/barrel-select`, one Select: Turbopack +72,949 B, webpack +90,253 B, `next dev` +227,148 B.

The Select page also loads FieldScope, which Select reads. `/barrel-select` under webpack includes
the barrel leak described in [Next.js](/docs/getting-started/next/#the-barrel-and-webpack).

**The static variants.** The fixture's `/icon-button-static` page (one `IconButtonStatic`) and
`/field-static` page (two `FieldStatic`s around NativeSelects, the markup of `/field-zero-js`) ship
no Nizivo client module and measure 0 B over `/button-only` in every mode: Turbopack, webpack,
webpack with `optimizePackageImports` and `next dev`. Against `/icon-button` and `/field-zero-js`
above, that is 20,802 B and 3,364 B less under Turbopack, and 62,742 B and 8,551 B less under
`next dev`. Production webpack already shipped nothing for the zero-JS paths. Week 7 also showed why
a lazy import was not used instead (`packages/react/W7-RESULTS.md`, section "D-aa"): a shell that
loads the leaf with `lazy(() => import())` still shipped the chain under Turbopack (+20,875 B),
which ships every client module the server graph reaches, static or dynamic.

### A pricing page

Everything here is server kind, so the page loads no Nizivo client module (the fixture's `/t0` page
renders the same components and measures 0 B in every mode, and its `/icons-server` page shows icons
rendered by a Server Component ship nothing). The call to action is a Button rendered as a plain
link.

### A settings form posted to a Server Action

Regional settings with three choices, each a NativeSelect. NativeSelect is server kind and
`FieldStatic` imports no client module, so the form ships no Nizivo client module. The Server Action
validates and redirects; a server error comes back in the URL and renders inline.

```tsx title="app/settings/page.tsx"
import { Button } from '@nizivo/react/button';
import { FieldStatic } from '@nizivo/react/field';
import { NativeSelect } from '@nizivo/react/native-select';
import { Stack } from '@nizivo/react/stack';
import { saveRegionalSettings } from './actions';
import { getSettings } from './data';

export default async function SettingsPage({
  searchParams,
}: {
  searchParams: Promise<{ error?: string }>;
}) {
  const [settings, { error }] = await Promise.all([getSettings(), searchParams]);
  return (
    <form action={saveRegionalSettings}>
      <Stack gap="6">
        <FieldStatic label="Language" name="language" required>
          {(control) => (
            <NativeSelect {...control} defaultValue={settings.language}>
              <option value="en-IN">English (India)</option>
              <option value="hi-IN">हिन्दी</option>
            </NativeSelect>
          )}
        </FieldStatic>
        <FieldStatic
          label="Time zone"
          name="timeZone"
          description="Order times and reports use it."
          error={error === 'timeZone' ? 'Choose a time zone from the list.' : undefined}
          required
        >
          {(control) => (
            <NativeSelect {...control} defaultValue={settings.timeZone}>
              <option value="Asia/Kolkata">India (IST)</option>
              <option value="Europe/London">United Kingdom</option>
              <option value="America/New_York">US Eastern</option>
            </NativeSelect>
          )}
        </FieldStatic>
        <FieldStatic label="Weekly summary email" name="digest">
          {(control) => (
            <NativeSelect {...control} defaultValue={settings.digest}>
              <option value="off">Off</option>
              <option value="mon">Mondays</option>
              <option value="fri">Fridays</option>
            </NativeSelect>
          )}
        </FieldStatic>
        <Button type="submit" variant="primary">
          Save
        </Button>
      </Stack>
    </form>
  );
}
```

```ts title="app/settings/actions.ts"
'use server';
import { redirect } from 'next/navigation';
import { updateSettings } from './data';

const TIME_ZONES = new Set(['Asia/Kolkata', 'Europe/London', 'America/New_York']);

export async function saveRegionalSettings(formData: FormData): Promise<void> {
  const timeZone = String(formData.get('timeZone') ?? '');
  if (!TIME_ZONES.has(timeZone)) redirect('/settings?error=timeZone');
  await updateSettings({
    language: String(formData.get('language')),
    timeZone,
    digest: String(formData.get('digest')),
  });
  redirect('/settings');
}
```

What the form gives up, compared with `Field`:

- `required` is checked by the browser with its own message bubble, not an inline message.
- Nothing moves focus to the field that failed or speaks the server error: a screen reader reads it
  when focus reaches the select (through its `aria-describedby`). `Field`'s announcer, which speaks a
  new error while focus stays in the field, exists only with FieldScope.

Adding a text field changes the answer. `Input` is client kind and reads FieldScope, so step 7 says
`Field`. Once one `Field` with a client control is on the page, FieldScope is loaded, `FieldStatic`
saves nothing, and the form validates one way only if every field uses `Field`:

```tsx
import { Field } from '@nizivo/react/field';
import { Input } from '@nizivo/react/input';

<Field label="Store name" name="storeName" required>
  <Input />
</Field>;
```

Mixing native-validated kinds in one form has a known catch: see
[Validation in mixed forms](/docs/components/field/#validation-in-mixed-forms).

### A dismissible notice from a Server Component

A split component whose JavaScript follows one prop. The notice shows until the user dismisses it;
the dismissal is a Server Action that sets a cookie, so the server stops rendering the Alert.

```tsx title="app/(shop)/layout.tsx"
import { cookies } from 'next/headers';
import { Alert, AlertDismiss } from '@nizivo/react/alert';
import { dismissPayoutNotice } from './actions';

export default async function ShopLayout({ children }: { children: React.ReactNode }) {
  const dismissed = (await cookies()).get('payout-notice')?.value === 'dismissed';
  return (
    <>
      {!dismissed && (
        <Alert
          title="Payouts move to daily on Nov 1"
          dismiss={<AlertDismiss onDismiss={dismissPayoutNotice} />}
        >
          No action needed.
        </Alert>
      )}
      {children}
    </>
  );
}
```

```ts title="app/(shop)/actions.ts"
'use server';
import { cookies } from 'next/headers';

export async function dismissPayoutNotice(): Promise<void> {
  (await cookies()).set('payout-notice', 'dismissed', { maxAge: 60 * 60 * 24 * 365 });
}
```

With `dismiss`, the page loads one client module, `alert/alert-dismiss.client` (+1,490 B under
Turbopack in the fixture's `/alert-dismiss`). Without it, the same Alert loads none.

## Common mistakes

**An IconButtonStatic with no name.** It has no tooltip and no `label`, so `aria-label` is its name.
TypeScript rejects the first line (and `label="…"`, which IconButtonStatic does not take); without a
name a screen reader announces only "button", and a development build warns in the console.

```tsx
<IconButtonStatic icon={<Trash />} />; // wrong: no accessible name
<IconButtonStatic aria-label="Delete product" icon={<Trash />} />; // right
```

**FieldStatic around a Nizivo Input, expecting it to wire itself.** FieldStatic provides no context
and wires only through its function child. TypeScript rejects a child that is not a function, and
plain JavaScript that passes one fails at render with "FieldStatic: children must be a function".
Spreading the argument on the Input
passes it the ids and ARIA attributes, but saves nothing: Input is client kind and its module reaches
FieldScope, and the inline native message and the announcer are still missing.

```tsx
// wrong: throws, the child is not a function
<FieldStatic label="Store name">
  <Input />
</FieldStatic>;

// wired, but no saving: use Field here
<FieldStatic label="Store name">{(control) => <Input {...control} />}</FieldStatic>;

// right
<Field label="Store name">
  <Input />
</Field>;
```

**A tooltip on a static button.** IconButtonStatic takes no `tooltip` prop (TypeScript rejects it).
Wrapping it in a Tooltip loads the same Tooltip code, and the tooltip then describes the button with
its own name, so a screen reader hears it twice. Use IconButton, which pairs the tooltip without the
duplicate description.

```tsx
// wrong: the Tooltip code ships anyway, and the name is read twice
<Tooltip.Root content="Bold">
  <Tooltip.Trigger render={<IconButtonStatic aria-label="Bold" icon={<Bold />} />} />
</Tooltip.Root>;

// right
<IconButton label="Bold" icon={<Bold />} />;
```

**Expecting `tooltip={false}` to ship nothing.** It runs no client code, and production webpack ships
none, but Turbopack and `next dev` still ship the tooltip chain (+20,802 B, +62,742 B). Use
`IconButtonStatic` for zero bytes in every mode.

**`'use client'` at the top of a page "to make it work".** Every component that file imports becomes
client code, server kind included. Keep the page a Server Component and put only the interactive part
in a small client component.

**Passing `onClick` from a Server Component.** React cannot send a function from the server to the
browser. Use a link, a form with a Server Action, or a client component that owns the handler.

**Measuring with `next dev`.** It ships unminified code for every client module the server graph
reaches. Compare production builds, and compare a page against the same page without the component.

## Outside Next.js

- **Vite (a single-page app):** there are no Server Components, so every imported component is in the
  bundle and runs, with handlers and state as usual ([In a client app](#in-a-client-app)). The kind still says which components work in server-rendered HTML before
  hydration. Vite drops modules a page does not use, so a static variant leaves out the Tooltip code
  or FieldScope when nothing else imports them; this has not been measured for the static variants
  yet.
- **Astro:** a component rendered without a `client:*` directive is static HTML with no JavaScript,
  whatever its kind. Server kind and the static variants need no directive. A client-kind component,
  or a split one used with its interactive prop (an IconButton with its tooltip, an Alert with
  `dismiss`), needs a `client:load` or `client:visible` island to work. See
  [Astro](/docs/getting-started/astro/#islands).
