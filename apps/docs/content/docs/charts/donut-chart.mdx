## Static or interactive

**Split.** DonutChart has no `'use client'`; it renders the ChartInteraction island over the ring
when its status is `'ready'` and `interaction` is `'nizivo'` (the default since M41), as AreaChart
and BarChart do. That island is its keyboard route: one Tab stop over the ring, the arrow keys over
the slices, the [ChartTooltip](/docs/charts/chart-tooltip/) card (see
[Accessibility](#accessibility)). `interaction="none"` renders no island: the ring is static, hovering
a segment or its legend row dims the others and swaps the centre in CSS alone, and the frame makes
no keyboard claim. In both modes the legend, with every value and share, and the data table carry
the same information without a pointer; `tableView="details"` shows the table to everyone. [How to
choose](/docs/guides/static-or-interactive/).

## Folding

`foldCategories(items, max, otherLabel, sort)` is the rule DonutChart applies, exported so a server
can compute the same slices:

1. Values that are not finite, or not above zero, are left out.
2. `sort="value"` (default) orders the rest largest first, ties in input order; `sort="none"` keeps
   input order.
3. The first `maxCategories` (clamped to 1–3) take `chart/cat-1`, `chart/cat-2` and `chart/cat-3`,
   in that order.
4. The rest add up into one slice in `chart/neutral` named `labels.other`. When exactly one category
   is left over, that slice keeps its own name.

## Props

<ChartProps />

`category` and `value` are an `Accessor`: a key of the datum whose values have the right type
(`category="name"`, which a Server Component can pass), or a `(datum, index) => value` function, as
in every chart. `format` defaults to `Intl.NumberFormat`'s own options (`{}`): a fractional value
shows its fraction. `totalFormat` defaults to `format` in compact notation with at most one
fraction digit, and `shareFormat` to `{ style: 'percent', maximumFractionDigits: 0 }`. All three are
plain `Intl.NumberFormatOptions`, as `@nizivo/react`'s Delta and Meter take them.

`labels` takes `Partial<DonutChartLabels>`, which extends `ChartFrameLabels` (its members are under

## Narrow widths

The chart lays itself out by its own width (ChartFrame is a size container), never the viewport's,
so it works the same in a sidebar, a card or on a phone, and on the server, which knows neither:

- Under 24rem, the legend moves under the ring and takes the full width: each row's name wraps in
  one flexible column, and its value and share never break. The ring takes up to the chart's whole
  width, centred. There is no room there for the island's card that would neither pass the
  chart's edge nor cover the ring, so it is not shown: the active slice's share and name fill the
  centre, its legend row (the others dimmed) shows its value, and the island still speaks it.
- A legend name wraps, a long word too, rather than running into its value, at every width.
- The centre steps down with the ring: Numeric/M over Body/S on a ring under 10rem. On a ring
  under 6rem the total no longer fits: it is clipped out of sight but stays in the markup, so a
  screen reader still reads it (it is in no legend row or table cell).

## Accessibility

- The ring is `aria-hidden`. The legend lists every slice with its value and share, and the data
  table has one row per slice: both are server HTML.
- The centre's total is readable; the per-slice centres shown on hover are `aria-hidden`.
- The legend renders in every status so the box does not move, but shows values and shares only when
  the chart is ready: an error never shows numbers beside "could not be loaded".
- With `interaction="nizivo"` (default), the island's item mode is the keyboard route (M41). The
  ring is one Tab stop (`role="application"`, named by `title` when it is a string, else
  `labels.points`; role description `labels.interaction`; described by `labels.hint`, visually
  hidden). Keyboard focus shows the card for the active slice: the first slice, or the last one a key or the pointer showed. ArrowRight and ArrowLeft move to the next and
  previous slice in data order, which is clockwise; the ring is never mirrored, so `dir="rtl"` does
  not flip the keys. Home and End go to the first and last slice. The active segment gets
  `data-highlighted`, which dims the other segments to opacity 0.35 and the other legend rows to
  0.45 and swaps the centre to its share and name, as hover does.
- The [ChartTooltip](/docs/charts/chart-tooltip/) card sits at the slice's centre, half-way through
  the band, and opens toward the legend: the slice's name as its title, one row (`labels.value`, a
  swatch in the slice's colour, the formatted value) and its share with `labels.ofTotal`
  ("52% of total"). Each keyboard move speaks the same through the polite region, joined with the
  list separators of the chart's `locale`; with `labels={{ value: 'Sales' }}`, "Online store, Sales,
  $64,120, 52%, of total" (`donut-chart-interaction.spec.tsx` in `packages/charts/test/browser`). A pointer
  shows the card for the segment under it and never speaks; over a gap or the hole the card stays
  as it is.
- Escape hides the card wherever focus is, as in the other island modes. On the focused ring it is
  consumed and stopped, so an enclosing dialog stays open, a native `<dialog>` or
  [Dialog](/docs/components/dialog/); with focus elsewhere it hides a card the pointer
  opened and still reaches an enclosing dialog (M41).
- With `interaction="none"`, hover is CSS only, with the same dimming, and the frame makes no
  keyboard claim. The hover state has no Escape; it adds no information the legend does not show.
  Pass `tableView="details"` where sighted keyboard users need the data table.
- Forced colours: the four slices take `Highlight`, `Canvas` (hollow), `CanvasText` and `GrayText`,
  each outlined in `CanvasText` (the active slice 3 px), and the legend marks inside the donut match
  them. Only Chromium's
  forced-colours emulation has been looked at.
- The ring fades in over `--nz-duration-chart-draw`, 0 ms under Reduced motion.

### Keyboard

With `interaction="nizivo"` (default):

<ChartsTable label="DonutChart keyboard">

| Keys                   | Action                                                                                                           |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Tab                    | Focuses the ring. A keyboard focus shows and speaks the active slice, the first one at first.                    |
| ArrowRight / ArrowLeft | The next or previous slice in data order (clockwise), whatever the page's direction: the ring is never mirrored. |
| Home / End             | The first or last slice.                                                                                         |
| Escape                 | Hides the card and clears the highlight, wherever focus is.                                                      |

</ChartsTable>

Source: `chart-interaction.client.tsx` in `packages/charts/src/_island` (item mode).
`donut-chart-interaction.spec.tsx` in `packages/charts/test/browser` checks it. With
`interaction="none"` the ring has no Tab stop and no keys.
