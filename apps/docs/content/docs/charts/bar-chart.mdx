## Static or interactive

**Split.** BarChart's bars, grid, tick labels and data table are server HTML. Its module imports
one client module, the ChartInteraction island, which it renders in column mode only when the
status is `'ready'` and `interaction` is `'nizivo'` (the default). With `interaction="none"` it
renders no island and the plot has no Tab stop: hovering a column dims the other bars and shows
that bar's own tooltip in CSS alone, which is hover-only and cannot be dismissed with Escape, so it
does not meet WCAG 1.4.13. The data table is then the screen-reader path; pass
`tableView="details"` so sighted keyboard users can reach the values too.

As with [AreaChart](/docs/charts/area-chart/#static-or-interactive), the shell imports its leaf:
Turbopack and `next dev` ship a client module that a page's server code imports, rendered or not,
so `interaction="none"` alone does not keep the island out of a Turbopack page. That follows from
AreaChart's `/chart-area-static` measurement in the Next.js fixture, which has no BarChart page
yet. This page has its
own route, so the island loads here and on the AreaChart page, and on no other page of this site.
[How to choose](/docs/guides/static-or-interactive/).

## Props

<ChartProps />

`x` and `y` are an `Accessor`: a key of the datum whose values have the right type (`x="date"`,
which a Server Component can pass), or a `(datum, index) => value` function. A `y` that is not a
finite number draws no bar and shows `labels.missing` in the table and the card; zero draws no
bar; a negative value hangs from the zero line. `format` defaults to `Intl.NumberFormat`'s own
options (`{}`), as in every chart: a fractional value shows its fraction. `axisFormat` defaults to
`format` in compact notation with at most one fraction digit.

`xTicks` (`ChartXTicks`): at most `max` x labels (BarChart: 8), the first and last always shown;
`every` sets the bars between labels. A label sits centred under its bar; the first and last, when
wider than their bar's band, are clamped inward to the plot's edges.

<ChartMembers name="ChartXTicks" />

The props marked as from `CartesianChartOptions` are the ones BarChart and
[AreaChart](/docs/charts/area-chart/) share, with the same names and types (one API shape across
the charts, M40). The defaults are the same too, except `xTicks.max`: 8 here, 6 for AreaChart.

`labels` takes `Partial<BarChartLabels>`, which extends `ChartFrameLabels` (its members are under
[Other exports](#other-exports)). The English defaults, in `barChartLabels`, on top of
[ChartFrame's](/docs/charts/chart-frame/#props):

## CSS hooks

<ChartCssHooks />

`--nz-bar-chart-aspect` is the body's aspect ratio (the design's 640 × 260), in place of ChartFrame's,
and `--nz-bar-chart-bar-size` the widest a bar gets (22 px); a bar is at most 52 % of its column.

## Accessibility

- The bars and the grid are `aria-hidden`; the server-rendered data table (one row per datum) is the
  accessible alternative. By default it is visually hidden and has no Tab stop, so it serves screen
  readers; the island is the keyboard path to each bar.
- With the island, the plot is one Tab stop: a `role="application"` layer named by the title (or
  `labels.points`), with the `labels.interaction` role description and the `labels.hint`
  description, rendered on the server. `application` stays until the manual screen-reader pass
  (M40). The arrow keys step one column at a time, every datum included (a datum with no finite
  value is still a column, read as `labels.missing`).
- One polite live region, empty in the server HTML, speaks the column a key move reaches: its
  title, the series' name and the value (the Basic example's last column: "Fri, Oct 30, Orders,
  313"), joined with the
  separators `Intl.ListFormat` writes in `locale` on the server. A pointer shows the card and says
  nothing.
- The active column carries `data-highlighted`: the other bars dim to opacity 0.35, not
  `chart/secondary` (§14.1), and the active bar keeps `chart/primary`. The tooltip is
  [ChartTooltip](/docs/charts/chart-tooltip/)'s card, beside the column's centre, and is
  `aria-hidden`.
- Against WCAG 1.4.13 (Content on Hover or Focus), the card is dismissable: Escape hides it and
  clears the highlight wherever focus is (Escape on the focused plot hides only the card, so an
  enclosing dialog stays open). It is persistent: no timeout. It never hides while the pointer is
  over the plot or the card, but it follows the band under the pointer, so it cannot be held on
  one bar: not "hoverable" in 1.4.13's sense. `chart-interaction-columns.spec.tsx` and
  `bar-chart-interaction.spec.tsx` in `packages/charts/test/browser` check column mode in
  Chromium, WebKit and Firefox. With `interaction="none"` there is no card: the CSS hover tooltip
  does not meet 1.4.13.
- Forced colours: bars draw in `CanvasText` (`Highlight` on the active column), grid lines in
  `GrayText` and the zero line in `CanvasText`; the card takes the system's `Canvas` and
  `CanvasText`, as every ChartTooltip does. Only Chromium's forced-colours emulation has been
  looked at.
- No stagger in the reveal: a per-bar delay would need an inline style. All bars grow together over
  `--nz-duration-chart-draw`, 0 ms under Reduced motion.

### Keyboard

<ChartsTable label="BarChart keyboard">

| Keys                   | Action                                                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tab                    | Focuses the layer. A keyboard focus shows and speaks the active column, the last one at first.                                                    |
| ArrowRight / ArrowLeft | The next or previous column on screen; on a mirrored plot (`xDirection="rtl"`, or `"auto"` on a right-to-left page) ArrowRight goes back in time. |
| Home / End             | The first or last column.                                                                                                                         |
| Escape                 | Hides the card and clears the highlight, wherever focus is.                                                                                       |

</ChartsTable>

Source: `chart-interaction.client.tsx` in `packages/charts/src/_island` (column mode). Touch: a tap
shows the column's card and keeps it after the finger lifts (synthetic pointer events only; real
touch hardware is not tested).
