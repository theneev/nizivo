## Static or interactive

**Split.** AreaChart's SVG, tick labels, legend and data table are server HTML. Its module imports
one client module, the ChartInteraction island, which it renders only when the status is `'ready'`
and `interaction` is `'nizivo'` (the default). With `interaction="none"` it renders no island and
the plot has no Tab stop. The data table is then the screen-reader path; pass
`tableView="details"` so sighted keyboard users can reach the values too.

As with Field and IconButton in `@nizivo/react`, the shell imports its leaf: Turbopack and
`next dev` ship a client module that a page's server code imports, rendered or not. This site's own
build (Next.js 16, Turbopack) loaded the island on a page that rendered only
`<AreaChart interaction="none" />`. To ship no chart JavaScript, draw the chart with a part that
imports no client module. The Next.js fixture's page for this case
(`fixtures/next/app/chart-area-static`, recorded in week 10) shows the same: Turbopack and
`next dev` ship the imported island (1,056 B gzip under Turbopack), and webpack ships nothing
(`fixtures/next/RESULTS.md`, "Week 10"). [How to choose](/docs/guides/static-or-interactive/).

**Long series.** Every point costs the page about 280 B of server HTML (the paths and a table row)
and, with the island, about 335 B of JSON in the RSC payload: a year of daily points is about 100 KB
of HTML and 120 KB of island props. Above about 90 points, bucket daily data weekly before passing
it in.

## Accessibility

- The picture is `aria-hidden`; the data table (one row per point, every series in a column) is the
  accessible alternative. The comparison line is decorative and its values are in the table.
- With the island, the plot is one Tab stop: a `role="application"` layer named by the title, with
  the `labels.interaction` role description and the `labels.hint` description, both rendered on
  the server. `application` is the role that lets a screen reader pass the arrow keys through; it is
  provisional until the manual screen-reader pass.
- One polite live region (`aria-live="polite"`, `aria-atomic="true"`), empty in the server HTML,
  speaks the point a key move reaches. Leaving the layer empties it, so coming back by keyboard
  speaks the active point again. A key that does not move the point (End at the last point) says
  nothing, as a slider at its end does. A pointer shows the point and says nothing (Figma 03).
- The tooltip card is `aria-hidden`: it repeats what the live region and the table say.
- Showing a point moves nothing in the layout, and moving it adds no layout shift: the crosshair
  and the dots move by `translate` (`chart-interaction.spec.tsx` sweeps a pointer across the plot).
- A card shown by the pointer hides with Escape only while the layer has focus. WCAG 1.4.13 asks
  for Escape without moving focus too; it does not fit the island's size budget yet (an open item).

### Keyboard

<ChartsTable label="AreaChart keyboard">

| Keys                   | Action                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------- |
| Tab                    | Focuses the layer. A keyboard focus shows and speaks the active point, the last point at first. |
| ArrowRight / ArrowLeft | The next or previous point; under `xDirection="rtl"` the arrows follow the screen.              |
| Home / End             | The first or last point.                                                                        |
| Escape                 | Hides the card; the point stays active.                                                         |

</ChartsTable>

and keeps the card after the finger lifts (synthetic pointer events only; real touch hardware is
not tested).
