## Static or interactive

**Split.** AreaChart's SVG, tick labels, legend and data table are server HTML. Its module imports
one client module, the ChartInteraction island, which it renders only when the status is `'ready'`
and `interaction` is `'nizivo'` (the default). With `interaction="none"` it renders no island and
the plot has no Tab stop. The data table is then the screen-reader path; pass
`tableView="details"` so sighted keyboard users can reach the values too.

As with Field and IconButton in `@nizivo/react`, the shell imports its leaf: Turbopack and
`next dev` ship a client module that a page's server code imports, rendered or not. To ship no
chart JavaScript, draw the chart with a part that imports no client module. The Next.js fixture's
page for this case (`fixtures/next/app/chart-area-static`, recorded in week 10) shows it: Turbopack
and `next dev` ship the imported island (1,056 B gzip under Turbopack in week 10; the island has
grown since, see [Sizes](/docs/charts/#sizes)), and webpack ships nothing
(`fixtures/next/RESULTS.md`, "Week 10"). Each charts page has its own route, so on this site the
island loads on this page and the [BarChart](/docs/charts/bar-chart/) page only. [How to choose](/docs/guides/static-or-interactive/).

**Long series.** Measured on 2026-10-20 (M40) with a comparison series and USD values, a year of
daily points (365) is about 82 KB of server HTML (15.5 KB gzip) and 164 KB of RSC payload (28.8 KB
gzip), of which 23 KB is the island's props: about 64 B of JSON a point (week 10: about 335 B).
The same year bucketed weekly (52 points) is 14 KB of HTML (3.1 KB gzip) and 26 KB of RSC payload
(5 KB gzip). `area-chart.server.test.tsx` in `packages/charts/test/ssr` holds the island's props
to 50 to 80 B a point at 365 points. Bytes no longer force bucketing at 90 points (13.9 KB gzip in
all, the island's code included), but on Figma's 720 px plot a daily year leaves 2 px a point and
365 arrow-key steps, so above about 90 points, bucket daily data weekly before passing it in.

## Props

<ChartProps />

`x`, `y` and `compare` are an `Accessor`: a key of the datum whose values have the right type
(`x="date"`, which a Server Component can pass), or a `(datum, index) => value` function. `format`
and `axisFormat` are plain `Intl.NumberFormatOptions`, as `@nizivo/react`'s Delta and Meter take
them; there are no presets.

`xTicks` (`ChartXTicks`): at most `max` x labels (AreaChart: 6), the last point always labelled.
When `every` is not given, a daily date series rounds the step up to whole weeks (Figma 03's Oct 1,
8, 15, 22 and the forced 30).

<ChartMembers name="ChartXTicks" />

The props marked as from `CartesianChartOptions` are the ones AreaChart and
[BarChart](/docs/charts/bar-chart/) share, with the same names and types (one API shape across the
charts, M40). The defaults are the same too, except `xTicks.max`: 6 here, 8 for BarChart.

`labels` takes `Partial<AreaChartLabels>`, which extends `ChartFrameLabels` (its members are under

## CSS hooks

<ChartCssHooks />

`--nz-area-chart-halo` is the ring around the end dot: the surface behind the chart. When the hook is unset, the ring takes the shared `--nz-surface` that `@nizivo/react`'s
[Card](/docs/components/card/) declares for its children (KpiTile and TrendCard are Cards, so a
tinted tile's halo is its own surface), else `--nz-bg-surface`. Charts read `--nz-surface` only if
it is there: without `@nizivo/react` on the page it is unset and the halo is `--nz-bg-surface`, and
`@nizivo/charts` does not depend on `@nizivo/react` (M42). The aspect ratio is ChartFrame's `--nz-chart-frame-aspect` (18 / 7).

## Accessibility

- The picture is `aria-hidden`; the data table (one row per point, every series in a column) is the
  accessible alternative. The comparison line is decorative and its values are in the table.
- With the island, the plot is one Tab stop: a `role="application"` layer named by the title, with
  the `labels.interaction` role description and the `labels.hint` description, both rendered on
  the server. `application` is the role that lets a screen reader pass the arrow keys through; it
  stays until the manual screen-reader pass (M40).
- One polite live region (`aria-live="polite"`, `aria-atomic="true"`), empty in the server HTML,
  speaks the point a key move reaches: the date, then each series' name and value, joined with the
  separators `Intl.ListFormat` writes in `locale` on the server. Hiding the card (Escape, the
  pointer leaving, leaving the layer) empties it, so the next key that shows the card speaks the
  active point again. A key that does not move the point (End
  at the last point) says nothing, as a slider at its end does. A pointer shows the point and says
  nothing (Figma 03).
- The tooltip card is `aria-hidden`: it repeats what the live region and the table say.
- Against WCAG 1.4.13 (Content on Hover or Focus), the card is dismissable: Escape hides it
  wherever focus is, a card the pointer opened included (Escape on the focused plot hides only the
  card, so an enclosing dialog stays open). It is persistent: no timeout. It never hides while the
  pointer is over the plot or the card, but it takes no pointer events, so it follows the point
  under the pointer and cannot be held on one point: not "hoverable" in 1.4.13's sense.
  `chart-interaction.spec.tsx` checks this in Chromium, WebKit and Firefox.
- Showing a point moves nothing in the layout, and moving it adds no layout shift: the crosshair
  and the dots move by `translate` (`chart-interaction.spec.tsx` sweeps a pointer across the plot).
- Right to left: see [Right to left](/docs/charts/#right-to-left) for what a page sees before and
  after the island hydrates.

### Keyboard

<ChartsTable label="AreaChart keyboard">

| Keys                   | Action                                                                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Tab                    | Focuses the layer. A keyboard focus shows and speaks the active point, the last point at first.                                                  |
| ArrowRight / ArrowLeft | The next or previous point on screen; on a mirrored plot (`xDirection="rtl"`, or `"auto"` on a right-to-left page) ArrowRight goes back in time. |
| Home / End             | The first or last point.                                                                                                                         |
| Escape                 | Hides the card, wherever focus is; the point stays active.                                                                                       |

</ChartsTable>

Source: `chart-interaction.client.tsx` in `packages/charts/src/_island`, checked in Chromium, WebKit and
Firefox by `chart-interaction.spec.tsx` in `packages/charts/test/browser`. Touch: a tap shows the point
and keeps the card after the finger lifts (synthetic pointer events only; real touch hardware is
not tested).
