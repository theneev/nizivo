Nizivo follows the Figma library, except where a value fails WCAG 2.2 AA, where Figma has no value yet,
or where a browser on the support floor cannot do what the design asks. Every difference is listed here,
read at build time from the file that owns it; none of it is typed by hand.

### Week 4: Menu, Tabs, TabNav and the overlays

<BuilderChoicesW4 />

Two week 4 behaviours differ from the APG patterns, and neither is in the Figma file:

- Enter on a Menu checkbox item toggles it and keeps the menu open, as Space does. The APG menu
  button closes the menu on Enter. Staying open lets a reader set several columns in one visit
  (D-ag).
- Tabs arrow keys follow the direction of the `locale` set on `NizivoConfig`, or the `dir` prop on
  `Tabs.Root`, which overrides it for that strip and the strips nested in its panels (week 7, the
  maintainer's decision). A `dir="rtl"`
  attribute set elsewhere on the page alone does not turn them, because nothing reads the DOM:
  without the locale or the prop, ArrowRight moves to the tab on the left in a right-to-left strip.

### Week 5

Week 5 added no component and no Figma facts file, so it has no new value to choose. It removed two
places where the shipped CSS leaned on a page reset, which the components must not do: Menu rows are
36 px as Figma draws them with or without a `border-box` reset, and a Button rendered as a link has
no underline.

### Week 7

Two values that are not in the Figma file, both the maintainer's decisions of 2026-10-16:

- **16 px text in fields under a coarse pointer.** Input, Textarea, NativeSelect and the Select
  trigger use Body/L or Label/L (16 px) instead of Figma's Body/M or Label/M (14 px) when the primary
  pointer is coarse, because iOS Safari zooms the page into a focused field whose text is under 16 px.
  The weights are Figma's. Heights stay on the 32/40/48 px scale; a Textarea row is Body/L's 25.6 px
  line there instead of 21 px. The Select list's rows stay at 14 px. A page that sets
  `--nz-input-font`, `--nz-textarea-font` or `--nz-native-select-font` replaces the font on every
  pointer, so it also owns the zoom.
- **A minimum size for bare triggers.** A `Dialog.Trigger` or `Tooltip.Trigger` with no `render`
  (its own unstyled `<button>`) is at least 24 by 24 px (`1.5rem`), the WCAG 2.2 2.5.8 minimum, and
  carries `nz-hit-target` for the 44 px coarse-pointer hit area. Figma draws every trigger as a
  Button, which is still the recommended composition.

### Week 8

One value that is not in the Figma file, the maintainer's decision of 2026-10-17:

- **Alert's dismiss is a small IconButton.** Figma draws the close as a bare 16 px glyph with no
  states. In code it is a tertiary `sm` IconButton: a 32 px button with IconButton's hover and
  pressed fills and focus ring, and in forced colours its `ButtonText` border. The glyph stays 16 px
  in `icon/secondary`, 16 px from the inline-end edge, and the button reaches into the padding, so the
  row is no taller than the title's line. It replaces week 2's 24 px button, whose hover changed only
  the glyph colour.

### Week 9

Figma's file of 2026-10-18 settled several week 3 to week 6 choices (the Select list, the Textarea's
padding and height, the chart fills, one border width, the spinner's speed), so the tables above
now record Figma's values where they apply. What still differs, with the maintainer's decisions of
2026-10-18:

- **The selected Select row keeps a tint.** Figma's Select Option draws the selected row with only
  Label/M Strong and a trailing check. The code also keeps the `--nz-bg-brand-subtle` fill it had
  (M36: "keep tint, for label, follow figma").
- **The Select check's column is always reserved.** Figma hides the check on unselected rows and the
  label takes its place; the code keeps the 16 px column on every row, so selecting never moves the
  text.
- **The Select list is as wide as its trigger.** Figma's Select Menu says "matches its width (min
  240)"; the code keeps the trigger's width as the minimum, with no 240 px floor.
- **An icon-only pending button shows no text under Reduced motion.** Figma's Accessibility page
  says "Spinner and skeleton loops stop; a text label shows". Button does that ("Publishing ·
  Loading…"). IconButton has no room for text: its spinner stops and `aria-disabled` stays, and
  nothing visible says it is loading. Show the progress in words next to it (a status line), or use
  a Button where a label fits. Open for the maintainer.
- **A Textarea's minimum height can be lowered.** Figma's 112 px minimum is the default;
  `--nz-textarea-min-block-size` changes it (for example to `0` for a one-line composer).
