---
title: Input
description: A single-line native text input in a bordered box, with optional icons and text affixes. Inside a Field it is labelled, described and validated by the Field.
keyboard:
  - keys: Tab
    action: Moves focus to the input. The whole box draws the focus outline; a press anywhere on the box, its icons or its affixes, focuses the input.
  - keys: Enter
    action: Submits the form the input belongs to (the browser's implicit submission). Inside a Field, a failed constraint shows its message under the input and focuses the first invalid control.
keyboardSource: a native `<input>` (`input.client.tsx`); the box's mousedown handler forwards focus to it. The browser lane (`test/browser/text-controls.spec.tsx`) checks the focus outline, the hit area and inline validation on submit.
---

## Static or interactive

**Client.** It always ships its client leaf, which reads its Field through FieldScope, so a page
with an Input also loads FieldScope. The server HTML is a native `<input>` that works before
hydration. [How to choose](/docs/guides/static-or-interactive/).

## Text size on touch screens

Under a coarse pointer (a phone or a tablet), the text, the placeholder and the affixes are 16 px
(Body/L) instead of 14 px (Body/M) at every size, because iOS Safari zooms the page into a focused
field whose text is smaller than 16 px. The box keeps its 32, 40 or 48 px height. `--nz-input-font`
replaces the font on every pointer, so a page that sets it also decides whether iOS zooms.
