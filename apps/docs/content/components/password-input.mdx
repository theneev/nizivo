keyboard:
  - keys: Tab
    action: Moves focus to the input, then to the toggle. The box draws the focus outline while the input has focus, the toggle its own while it does.
  - keys: Space, Enter
    action: On the toggle, shows or hides the password.
  - keys: Enter
    action: In the input, submits its form. The password is hidden again on submit.

## Static or interactive

**Client.** It always ships its client leaf, which reads its Field through FieldScope, so a page
with a PasswordInput also loads FieldScope. The server HTML is a native password input that works
before hydration; the toggle works once the page has hydrated.
[How to choose](/docs/guides/static-or-interactive/).

In a client app (a Vite or React Router single-page app, or a `'use client'` file) it is an ordinary React component: event handlers, refs and state work as usual. [In a client app](/docs/guides/static-or-interactive/#in-a-client-app).

## The toggle

The toggle is a button with a constant name, "Show password" (`labels.toggle`), and `aria-pressed`:
a screen reader hears "Show password, toggle button, pressed" while the password shows. Its mark is
the internal `eye` glyph while the password is hidden and `eye-off` while it shows; `showIcon` and
`hideIcon` replace them. `onVisibleChange(visible, details)` reports each change, with
`details.reason` `'toggle'` or `'submit'`.

## Hidden again on submit

When its form submits, the password turns back into a password field before the form's handler or
action runs, so the plain text is not left on screen and a password manager sees a password field.

## Autocomplete

`autoComplete` is `current-password` by default, for signing in. Pass `new-password` where the user
chooses one, so a password manager offers to generate it. Spell check and autocapitalisation are
off.
