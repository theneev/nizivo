title: TabNav
description: Links styled as tabs, for views that are URLs (status filters, sub-pages). A navigation landmark of plain links with `aria-current="page"` on the current one, server-rendered with no JavaScript; a router's link goes in through `render`. In-page views with panels are Tabs.
keyboard:
  - keys: Tab, Shift+Tab
    action: Moves between the links, as on any link.
  - keys: Enter
    action: Follows the focused link.
keyboardSource: native `<a>` elements in a `<nav>` (`tab-nav.tsx`, no client code). The browser lane (`test/browser/tabs.spec.tsx`) checks Tab between links and the focus outline.
---

## Static or interactive

**Server.** It ships no client JavaScript when a Server Component renders it, in every Next.js build
mode; its code is bundled only when a client component (a `'use client'` file) imports it. Its links
are plain `<a>` elements. A router link passed through `render` is the router's own code: on the
Next.js fixture's `/tab-nav` page, three links through `next/link` load no Nizivo module and 3,302 B
(gzip, Turbopack) of Next's. It is the static alternative to Tabs when every view is a URL. [How to
choose](/docs/guides/static-or-interactive/).

In a client app (a Vite or React Router single-page app, or a `'use client'` file) it is an ordinary React component: event handlers, refs and state work as usual. [In a client app](/docs/guides/static-or-interactive/#in-a-client-app).
