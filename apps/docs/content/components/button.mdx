## Static or interactive

**Server.** It ships no client JavaScript when a Server Component renders it, in every Next.js build
mode; its code is bundled only when a client component (a `'use client'` file) imports it.

`onClick` works as on any `<button>`. In a client app (a Vite or React Router single-page app, or a
`'use client'` file) pass it, refs and state as usual
([In a client app](/docs/guides/static-or-interactive/#in-a-client-app)). Only a Server Component
cannot pass it, which is React's rule for every component: there, use `type="submit"` in a
`<form action={serverAction}>`, `render={<a href="…" />}`, or a client component that owns the
handler. [How to choose](/docs/guides/static-or-interactive/).

## Pending

`pending` replaces the leading icon with a spinner, keeps the label, and keeps the button focusable
with `aria-disabled`, swallowing clicks. The spinner turns once every 800 ms (`--nz-duration-spin`,
Figma's `duration/spin`). Under Reduced motion (the OS setting, or `data-nz-motion="reduce"` on an
ancestor) it stops, and the text "Loading…" shows in the label's place, so the wait is still
visible without movement (Figma's Accessibility page: "Spinner and skeleton loops stop; a text label
shows"). The text and the label share one space, so the button keeps its width when `pending`
starts (it grows only if "Loading…" is wider than the label). Where the text does not fit, it ends
in an ellipsis.

```tsx
<>
  {/* Reduced motion: the spinner stops and "Loading…" replaces "Publishing" */}
  <Button pending>Publishing</Button>
  <Button pending labels={{ pending: 'Wird geladen…' }}>
    Veröffentlichen
  </Button>
</>
```

The label is only made transparent, so it stays in the accessible name, after the text on screen:
"Loading… Publishing" (WCAG 2.5.3, the visible words are part of the name). Under default motion the
text is not rendered visibly and the name is the label. Assistive technology also learns the state
from `aria-disabled`. `labels={{ pending: '' }}` shows no text and keeps the label visible. The
markup is the same in both motion modes; only CSS reads the preference.

Translate the text with `labels.pending`. It is set per instance: 0.1.0 has no app-wide labels, and
Button, a server component, could not read them from context anyway. A localised app wraps Button
once and uses the wrapper everywhere:

```tsx
import { Button, type ButtonProps } from '@nizivo/react/button';

const strings = { loading: 'Wird geladen…' }; // the app's own message catalogue

export function AppButton({ labels, ...props }: ButtonProps) {
  return <Button labels={{ pending: strings.loading, ...labels }} {...props} />;
}
```
