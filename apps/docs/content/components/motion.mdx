## Static or interactive

**Client.** `CountUp` is a client module (`count-up.client.tsx`), the one client part of the
dashboard set, so it always ships its code. Its server HTML is the final formatted value in
NumberValue's `<data>` element, so the number is right before hydration and without JavaScript; the
client only animates it. For a number that does not count, use
[NumberValue](/docs/components/number-value/), which ships nothing. [How to
choose](/docs/guides/static-or-interactive/).

## When it counts

It counts with `requestAnimationFrame`, only while the element is in the viewport. An element
mounted on the client counts from `from` (default 0). An element that was already on screen when
the server HTML hydrated keeps its number: its reader has seen it. An element off screen counts when
it first comes into view. A new `value` counts from the number on screen when the element is in
view, and shows at once when it is not.

The duration is `--nz-duration-count-up` (900 ms), read from the element; a `duration` prop in
milliseconds replaces it. Under `prefers-reduced-motion: reduce` or `data-nz-motion="reduce"` the
token is 0 ms and the value shows at once, whatever `duration` says
([Motion](/docs/foundations/motion/)). The curve is `cubic-bezier(0, 0, 0, 1)`, the same curve as
`--nz-easing-enter`, which was proposed for count-up; it is written into the code and the token is
not read, so overriding the token does not change it. The design defines no easing for count-up.

## Accessibility

The counting digits are `aria-hidden`; a visually hidden copy beside them holds the final value,
which is what assistive technology reads. There is no live region, so nothing is announced while it
counts or when `value` changes. While counting, the digits keep the final string's width, so nothing
around them moves.

An early proposal put this in a separate `@nizivo/motion` package; the plan put it at the
`@nizivo/react/motion` subpath instead (ARCHITECTURE.md §13.4).
