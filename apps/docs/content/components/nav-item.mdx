## Static or interactive

**Server.** It ships no client JavaScript when a Server Component renders it, in every Next.js build
mode; its code is bundled only when a client component (a `'use client'` file) imports it. It is a
plain `<a>`; a router link passed through `render` is the router's own code. The page says which
item is `current`, because it knows its own route (a router's `usePathname` needs a client
component). [How to choose](/docs/guides/static-or-interactive/).

In a client app (a Vite or React Router single-page app, or a `'use client'` file) it is an ordinary React component: event handlers, refs and state work as usual. [In a client app](/docs/guides/static-or-interactive/#in-a-client-app).

## A list of items

NavItem is one link. Put the items in a `<nav>` with an `aria-label`, around a `<ul>` with one
`<li>` per item, so assistive technology announces a navigation landmark and the number of
destinations. A list of NavItems needs no component of its own.

## The collapsed rail

Collapsed is not a prop. In a [Sidebar](/docs/components/sidebar/) folded to the icon rail (from
640 px to 1280 px, or with `collapsed`), each item becomes a 40 px square around its icon. The label
and the count leave the layout but stay in the DOM, so the link keeps its accessible name ("Orders
12"), and a count shows as a dot on the icon. In a Sidebar, use `SidebarItem` from
`@nizivo/react/sidebar`: the same link, with a Tooltip that shows its label in the rail (the example
below). Give every item an `icon` in a sidebar that collapses.

## Height and hover

The row is a fixed 40 px with or without a count (Figma's height followed its content: 40 with the
count pill, 38 without). A long label ends in an ellipsis. The hover fill is `bg/muted`: Figma's
`bg/hover` equals the sidebar's `bg/canvas` in light mode, so its hover could not be seen.
