## Static or interactive

**Client.** It always ships its client leaf, which wires it to a Field. The server HTML is native
radios or checkboxes, so arrows, Space and submission work before hydration. [How to
choose](/docs/guides/static-or-interactive/).

In a client app (a Vite or React Router single-page app, or a `'use client'` file) it is an ordinary React component: event handlers, refs and state work as usual. [In a client app](/docs/guides/static-or-interactive/#in-a-client-app).

## One value or several

By default the chips are radios under `role="radiogroup"`: `value` and `defaultValue` are strings and
`onValueChange` receives the checked value. With `multiple` they are checkboxes under `role="group"`:
`value` and `defaultValue` are arrays, `onValueChange` receives every checked value in document
order, and the form submits one entry per checked chip (`formData.getAll(name)`). `required` applies
to one value only: on checkboxes the browser would require every one.

## Swatches

A product colour is data, not a token. Pass an element with that background in `leading`, such as
`<span style={{ background: '#2e5a3c' }} />`, or an image; it fills a 24 px circle with a thin inner
ring, so white and cream stay visible. A chip with a swatch and no text needs an `aria-label`.

## Unavailable or disabled

`unavailable` (out of stock) keeps the swatch's colour, draws a diagonal strike and describes the
chip as `labels.unavailable` ("Unavailable"; pass `labels={{ unavailable: 'Sold out' }}` on the
group). It can still be chosen, so a shopper can pick a sold-out size and be offered "Notify me";
add `disabled` to stop that. `disabled` greys the chip out and takes it out of the keyboard order, as
a native disabled input.

## No size jump

The edge is an inset ring, not a border: selecting turns it into a 2 px brand ring in the same box,
so a chip never grows on select (the design's grew from 90 × 40 to 92 × 42).
