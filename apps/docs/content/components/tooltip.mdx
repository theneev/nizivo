## Static or interactive

**Client.** It always ships React Aria's tooltip and overlay code (+19,625 B gzip under Turbopack
for one Tooltip on the Next.js fixture), once per page however many tooltips it has. Information a
user needs belongs in visible text; for an icon-only action, IconButton pairs the tooltip for you.
[How to choose](/docs/guides/static-or-interactive/).

## The trigger

Compose a Button into the trigger; it is still the recommended look:

```tsx
<Tooltip.Trigger render={<Button variant="tertiary">Export</Button>} />
```

For an icon-only action, use an [IconButton](/docs/components/icon-button/): it pairs itself with a
Tooltip that shows its `label`, so it needs no `Tooltip.Root`.

A bare `<Tooltip.Trigger>` is a plain, unstyled `<button>`, but it has a minimum size of its own: at
least 24 by 24 CSS pixels around a short text or a single glyph, the minimum target of WCAG 2.2 success
criterion 2.5.8 (Target Size, Minimum), so two side by side still meet it. It also carries
`nz-hit-target`, so under a coarse pointer it gets the same 44 px hit area as every standalone
pressable. A trigger you render yourself through `render` keeps its own size and gets neither.

A trigger inside running text, such as a word in a sentence that shows a tooltip, is the exception:
render your own element through `render` there. The 24 px minimum would make its line taller than
the others, and under a coarse pointer the 44 px hit area would reach into the lines above and below
and take taps meant for a link there. WCAG 2.2 2.5.8 exempts a target inside a sentence, so the
inline element needs neither.
