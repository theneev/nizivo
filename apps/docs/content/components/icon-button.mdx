---
title: IconButton
description: A square button that shows only an icon. Its required label is the button's accessible name and, by default, the text of a tooltip shown on hover and keyboard focus.
keyboard:
  - keys: Tab
    action: Moves focus to the button and shows its tooltip at once. The tooltip repeats the name, so the button is not described by it.
  - keys: Enter, Space
    action: Activates the button. A pending button stays focusable and swallows the activation.
  - keys: Escape
    action: Hides the tooltip; focus stays on the button.
keyboardSource: a native `<button>` (`icon-button.tsx`); the tooltip is react-aria-components 1.22.1 `TooltipTrigger` through Nizivo's Tooltip (`icon-button.client.tsx`). The Next fixture and the browser lane (`test/browser/icon-button.spec.tsx`) check showing on focus, Escape and the missing aria-describedby.

## Static or interactive

**Split.** The default tooltip ships the tooltip leaf and the Tooltip code (+20,802 B gzip under
Turbopack, once per page). `tooltip={false}` runs no client code, but Turbopack and `next dev` still
ship that code, because the shell imports the leaf; `IconButtonStatic`, from the same import path,
imports no client module. [How to choose](/docs/guides/static-or-interactive/).

In a client app (a Vite or React Router single-page app, or a `'use client'` file) it is an ordinary React component: event handlers, refs and state work as usual. [In a client app](/docs/guides/static-or-interactive/#in-a-client-app).

```tsx
import { IconButton, IconButtonStatic } from '@nizivo/react/icon-button';

<IconButton label="Delete product" icon={<Trash />} />; // the tooltip shows "Delete product"
<IconButtonStatic aria-label="Delete product" icon={<Trash />} />; // no tooltip, no client module
```

Use `IconButtonStatic` only where something visible already names the action for sighted users,
such as a column header; otherwise keep the tooltip. It takes no `label`, `tooltip` or `shortcut`
(TypeScript rejects them); pass `aria-keyshortcuts` yourself to announce a shortcut.

## Bundle size with Turbopack

`<IconButton tooltip={false}>` renders its button on the server and runs no client code, and
production webpack ships none of the tooltip code for it. Turbopack and `next dev` ship every client
module a page's server code imports, rendered or not, so the IconButton's tooltip leaf and the Tooltip
code still reach the page. Measured on the Next fixture (gzip of the page's client chunks, a page
with one `<IconButton tooltip={false}>` minus a page with one Button): Turbopack production
+20,802 B, production webpack 0 B, `next dev` +62,742 B (unminified), the same as a page that shows
the tooltip.
`IconButtonStatic` avoids it: its module imports no client code, so a page that renders only
`IconButtonStatic` ships none of the tooltip code in any mode (the fixture's `/icon-button-static`
page: 0 B over the Button page under Turbopack, webpack and `next dev`). On a page that
already loads the Tooltip code for something else, it saves nothing. `Dialog.Close` and
`AlertDismiss` write the IconButton markup themselves, so they do not import the tooltip.

## Pending

`pending` replaces the glyph with a spinner and keeps the button focusable with `aria-disabled`,
swallowing clicks. The spinner turns once every 800 ms (`--nz-duration-spin`). Under Reduced motion
it stops upright. A Button then shows "Loading…" after its label, but an icon-only button has no
room for text, so nothing visible says it is loading: when the wait is more than a moment, say so in
words next to it (a status line such as "Deleting…"), or use a Button with a label. This differs
from Figma's rule ("Spinner and skeleton loops stop; a text label shows") and is listed under
[Deviations](/docs/deviations/).
