## Unstable

It ships at `@nizivo/react/unstable/command-menu`, outside the semver promise, until it has stayed
the same in the design for two sync cycles. The search loads on the first open.

## Static or interactive

**Client.** It is the Dialog with React Aria's Autocomplete inside. The server renders the trigger;
the dialog renders only after hydration, when it opens. [How to choose](/docs/guides/static-or-interactive/).

## Parts

`CommandMenu.Root` holds whether it is open and registers its shortcut (`hotkey`, `'mod+k'` by
default; `null` for none). `CommandMenu.Trigger` opens it from the pointer and touch, and names the
shortcut through `aria-keyshortcuts`. `CommandMenu.Popup` is the dialog; in it, `CommandMenu.Input`
(the search row, with an "esc" hint), `CommandMenu.List` of `CommandMenu.Group`s with a heading and
their `CommandMenu.Item`s, and `CommandMenu.Footer`, the keys as the design shows them.

## Rows

An item is a link (`href`) or an action (`onAction`, in a client component); choosing it closes the
menu. `icon` draws a 20 px mark before its text, `kind` says what it is at the row's end ("Product",
"Order"), and `shortcut` draws its own Kbd and announces it. The search matches `textValue`, or the
item's text when it is a string. `filter` on the Popup is `'contains'` (default) or `'startsWith'`.
A Group's `limit` shows at most that many of its matching rows, and the arrow keys skip the rest; a
Group with no matching row hides with its heading.

## Long lists

Set `virtualized` on the List for hundreds of rows or more: only the rows in view are in the page,
in a fixed 20rem box, and the arrow keys, the search and the spoken count still cover every row. The
code that does it loads only for a virtualized list.

## Results from a server

Pass `filter="none"` and the menu shows every item you give it, unfiltered. `onQueryChange` on the
Popup runs as the reader types (and with `''` when Escape clears the field), so fetch there and
render the results as items; `query` makes the field's text controlled. Set `loading` on the List
while a request is on its way: the list is busy, and shows "Searching…" in place of "No results"
while it has no rows.

```tsx
<CommandMenu.Popup filter="none" onQueryChange={search}>
  <CommandMenu.Input />
  <CommandMenu.List loading={pending}>
    {results.map((r) => (
      <CommandMenu.Item key={r.id} href={r.href} kind={r.kind}>
        {r.title}
      </CommandMenu.Item>
    ))}
  </CommandMenu.List>
</CommandMenu.Popup>
```

## The count

Once the typing stops, the menu says how many rows show ("Results: 3", or "No results"), politely,
from a live region outside the list. It says nothing when it opens. `labels.results` takes
`{count}`, and a plural object (`PluralLabel` from `@nizivo/react/i18n`) in other languages.

## Shortcuts

The menu's shortcut is registered in `@nizivo/react/hotkeys`, one list for the whole page that a
help dialog can read with `useHotkeys`. `useHotkey` and `registerHotkey` add your own: they never
fire during an IME composition or while the reader types in a field, unless `allowInInputs`, and a
single printable key with no modifier warns in development (WCAG 2.1.4).
