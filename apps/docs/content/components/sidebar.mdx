## Static or interactive

**Server.** It ships no client JavaScript when a Server Component renders it, in every Next.js build
mode; its code is bundled only when a client component (a `'use client'` file) imports it. The width
follows the viewport through CSS, so the server and the browser render the same markup. [How to
choose](/docs/guides/static-or-interactive/).

In a client app (a Vite or React Router single-page app, or a `'use client'` file) it is an ordinary React component: event handlers, refs and state work as usual. [In a client app](/docs/guides/static-or-interactive/#in-a-client-app).

## Parts

- `Sidebar.Root`: a `<nav>` landmark named "Primary" (`labels.nav`, or your own `aria-label`).
- `Sidebar.Header`: the store, on a card. `mark` draws Figma's 32 px Store mark (an initial, or a logo
  image that fills it), `title` the store's name and `description` the line under it. Pass
  `render={<a href="/" />}` to make it a link home, or a store switcher's trigger.
- `Sidebar.Content`: the destinations, `NavItem`s 4 px apart.
- `Sidebar.Footer`: pushed to the bottom, for Settings.

## Widths

The width is the `layout/sidebar` token: 264 px from 1280 px (`--nz-lg`), the 72 px icon rail from
640 px, and below 640 px the Sidebar is not shown, because the MobileTabBar is the navigation there
(M49; Figma's frames are drawn at 248 and 76 px). The 1280 px threshold is provisional until design
confirms it. An app with its own collapse control passes `collapsed`: `true` keeps the rail and
`false` the full width at every width from 640 px. Store the choice where the server can read it, a
cookie for example, so the first paint already has the right width.

## The rail

In the rail each NavItem is a 40 px square around its icon, and the header keeps only its mark. The
labels and the counts stay in the DOM as the links' names ("Orders 12"), and a count shows as a dot.
Hovering or focusing an item shows its label beside it, past the rail's edge, with no tooltip script.
Give every item an `icon`. The rail is a size container (`nz-sidebar`), so NavItem folds whenever its
Sidebar is rail-narrow, whatever made it so.

## Height and scrolling

The Sidebar sticks to the top and is as tall as the viewport (`--nz-sidebar-block-size`). Expanded, a
long list scrolls inside it. The rail does not clip, so the labels can show past its edge; its
destinations fit a tablet's height.

Hooks: `--nz-sidebar-width`, `--nz-sidebar-block-size`, `--nz-sidebar-bg`, `--nz-sidebar-border`,
`--nz-sidebar-mark-bg`.
