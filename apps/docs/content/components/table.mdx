description: A native table in server-rendered parts, for orders, products and customers. Rows can link to a detail page as a whole, columns sort through the URL, number columns line up, and rows can be selected for bulk actions with one small client island.
keyboard:
  - keys: Tab
    action: Reaches each row's link, then any control in a row (a selection checkbox included), then the sort links in the header, in document order. The table and its cells take no focus.
  - keys: Space
    action: On a selection checkbox, checks or clears it; on the header's, every row.
  - keys: Shift + click
    action: On a row's checkbox, gives every row between it and the last one clicked the same state.
  - keys: Escape
    action: Inside a Table.Selection with rows selected, clears them; with none, does nothing, so an enclosing Dialog still closes.
  - keys: Enter
    action: On a row's link, opens the row; on a sort link, loads the page sorted by that column.
keyboardSource: Native table elements, links and checkboxes; Table.Selection's own listener for select-all, Shift-click and Escape; no engine, no grid role. Checked by the browser lane (test/browser/table.spec.tsx) in Chromium, Firefox and WebKit.

## Static or interactive

**Server**, with one client part. Every part but `Table.Selection` renders native table markup with
no client JavaScript: `Table.Container` (a `<div>`, the border and the horizontal scroll),
`Table.Root` (`<table>`), `Table.Caption`, `Table.Header`, `Table.Body`, `Table.Footer`,
`Table.Row`, `Table.Head` (`<th>`), `Table.Cell`, `Table.SortButton`, `Table.RowLink`,
`Table.SelectAll` and `Table.SelectRow`. `Table.Selection` is one client island around the whole
table; a page without it ships none of its code. It is a table, not a grid: arrow keys do not move
between cells, and assistive technology reads it as a table.
[How to choose](/docs/guides/static-or-interactive/).

## Name every table

Give the table a `Table.Caption`. When a card heading already says the same words, keep the caption
and pass `visuallyHidden`, or drop it and point the table at the heading with `aria-labelledby`.

## Rows that link

`<Table.Row interactive>` with a `Table.RowLink` in it (usually the first cell, as Figma's Order Row
draws the order number) makes the whole row the link's hit area and shows `bg/hover` on hover.
Buttons and other links in the row stay above it. Pass the router's link with
`render={<Link href="/orders/1042" />}`.

## Sorting

The URL holds the sort. Put a `Table.SortButton` in each sortable `Table.Head`, with `href` to the
same page sorted by that column (`render={<Link href="…" />}` for the router's link), and pass
`sort="ascending"` or `sort="descending"` to the column the page is sorted by: its `<th>` gets
`aria-sort`, and the arrow follows. With neither `href` nor `render`, `Table.SortButton` is a
`<button type="button">` for your own handler.

## Selecting rows

Put a `Table.SelectRow` in each row and a `Table.SelectAll` in the header, and wrap the table in
`Table.Selection`. Each row's box is a native checkbox that submits its `value` under `name`
(`ids` by default) with its form, so a bulk action works before any JavaScript runs: pass `form`
with the id of a form outside the table, as the example's "Archive selected" does. Give every row's
box its own name (`aria-label="Select order 1042"`). A checked row paints `bg/brand-subtle` through
CSS, with no script.

`Table.Selection` adds what a native checkbox cannot do: the header's box checks or clears every
row and shows the mixed state when only some are selected, Shift-click selects a range, and Escape
clears the selection. A client owner hears every change through `onSelectionChange(ids)`; a Server
Component reads the selection from the submitted form. Rows with `disabled` boxes are left out.

## Numbers and dates

`numeric` on a `Table.Head` and the `Table.Cell`s under it end-aligns them in tabular figures
(Numeric/M in cells). Format dates and money with `Intl` and an explicit `timeZone`, so the server
and the browser print the same text.

## Layout

Figma: a 12 px radius with a `border/subtle` stroke; the header on `bg/subtle` in Label/M; cells
12 / 20 px, a `border/subtle` line under each row. A table wider than its container scrolls inside
it; when its rows hold no link or control, give `Table.Container` a `label`, which names it as a
scrollable region and puts it in the Tab order, so a keyboard user can reach it and scroll it with the
arrow keys (Safari and Firefox do not focus a scroller on their own). `selected` on a row paints `bg/brand-subtle`. Hooks: `--nz-table-bg`, `--nz-table-border`,
`--nz-table-radius`, `--nz-table-header-bg`, `--nz-table-cell-padding-block`,
`--nz-table-cell-padding-inline`, `--nz-table-row-bg-hover`, `--nz-table-row-bg-selected`.
