## Static or interactive

**Server.** Every part renders native table markup with no client JavaScript: `Table.Container` (a
`<div>`, the border and the horizontal scroll), `Table.Root` (`<table>`), `Table.Caption`,
`Table.Header`, `Table.Body`, `Table.Footer`, `Table.Row`, `Table.Head` (`<th>`), `Table.Cell`,
`Table.SortButton` and `Table.RowLink`. It is a table, not a grid: arrow keys do not move between
cells, and assistive technology reads it as a table. Row checkboxes for bulk actions are a subpath of
their own, [TableSelection](/docs/components/table-selection/), so a page that imports
`@nizivo/react/table` loads no client module in any bundler.
[How to choose](/docs/guides/static-or-interactive/).

In a client app (a Vite or React Router single-page app, or a `'use client'` file) it is an ordinary React component: event handlers, refs and state work as usual. [In a client app](/docs/guides/static-or-interactive/#in-a-client-app).

## Name every table

Give the table a `Table.Caption`. When a card heading already says the same words, keep the caption
and pass `visuallyHidden`, or drop it and point the table at the heading with `aria-labelledby`.

## Rows that link

`<Table.Row interactive>` with a `Table.RowLink` in it (usually the first cell, as the design's Order Row
draws the order number) makes the whole row the link's hit area and shows `bg/hover` on hover.
Buttons and other links in the row stay above it. Pass the router's link with
`render={<Link href="/orders/1042" />}`.

## Sorting

**In the URL** (a Server Component, or any page whose sort should survive a reload or a shared link):
put a `Table.SortButton` in each sortable `Table.Head`, with `href` to the same page sorted by that
column (`render={<Link href="…" />}` for the router's link), and pass `sort="ascending"` or
`sort="descending"` to the column the page is sorted by: its `<th>` gets `aria-sort`, and the arrow
follows.

**In state** (a client component): with neither `href` nor `render`, `Table.SortButton` is a
`<button type="button">` for your own handler. Keep the column and direction in `useState`, sort
the rows, and pass `sort` to the sorted column's `Table.Head`:

```tsx
<Table.Head sort={column === 'name' ? direction : undefined}>
  <Table.SortButton onClick={() => sortBy('name')}>Product</Table.SortButton>
</Table.Head>
```

[In a client app](/docs/guides/static-or-interactive/#in-a-client-app) has the whole example, live.

## Numbers and dates

`numeric` on a `Table.Head` and the `Table.Cell`s under it end-aligns them in tabular figures
(Numeric/M in cells). Format dates and money with `Intl` and an explicit `timeZone`, so the server
and the browser print the same text.

## Layout

A 12 px radius with a `border/subtle` stroke; the header on `bg/subtle` in Label/M; cells
12 / 20 px, a `border/subtle` line under each row. A table wider than its container scrolls inside
it; when its rows hold no link or control, give `Table.Container` a `label`, which names it as a
scrollable region and puts it in the Tab order, so a keyboard user can reach it and scroll it with the
arrow keys (Safari and Firefox do not focus a scroller on their own). `selected` on a row paints `bg/brand-subtle`. Hooks: `--nz-table-bg`, `--nz-table-border`,
`--nz-table-radius`, `--nz-table-header-bg`, `--nz-table-cell-padding-block`,
`--nz-table-cell-padding-inline`, `--nz-table-row-bg-hover`, `--nz-table-row-bg-selected`.
