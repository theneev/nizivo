## Static or interactive

**Server**, with one client part. `TableSelectAll` and `TableSelectRow` render native checkboxes with
Checkbox's look and no client JavaScript; `TableSelection` is one client island around the whole
table. Import them from `@nizivo/react/table-selection`, next to `Table` from
`@nizivo/react/table`: a page that does not use selection loads none of it, under Turbopack and
webpack alike. [How to choose](/docs/guides/static-or-interactive/).

In a client app (a Vite or React Router single-page app, or a `'use client'` file) it is an ordinary React component: event handlers, refs and state work as usual. [In a client app](/docs/guides/static-or-interactive/#in-a-client-app).

## Bulk actions

Put a `TableSelectRow` in each row and a `TableSelectAll` in the header, and wrap the table in
`TableSelection`. Each row's box is a native checkbox that submits its `value` under `name`
(`ids` by default) with its form, so a bulk action works before any JavaScript runs: pass `form`
with the id of a form outside the table, as the example's "Archive selected" does. Give every row's
box its own name (`aria-label="Select order 1042"`). A checked row paints `bg/brand-subtle` through
CSS, with no script.

`TableSelection` adds what a native checkbox cannot do: the header's box checks or clears every
row and shows the mixed state when only some are selected, Shift-click selects a range, and Escape
clears the selection. A client owner hears every change through `onSelectionChange(ids)`; a Server
Component reads the selection from the submitted form. Rows with `disabled` boxes are left out.
