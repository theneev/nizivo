Placed directly inside a Field, or through a function child, a NativeSelect is wired as plain
attributes with no client code. It keeps the browser's own validation bubble rather than the Field's
inline message, so do not mix it with Field-wired client controls in one native-validated form (see
[Field](/docs/components/field/#validation-in-mixed-forms)).

## Static or interactive

**Server.** It ships no client JavaScript when a Server Component renders it, in every Next.js build
mode; its code is bundled only when a client component (a `'use client'` file) imports it. It is the
static alternative to Select when the browser's own picker fits. Inside a `Field` (placed directly
or through a function child) it is wired with no client code, but Turbopack and `next dev` still
ship the Field's FieldScope module; `FieldStatic` ships none. [How to
choose](/docs/guides/static-or-interactive/).

In a client app (a Vite or React Router single-page app, or a `'use client'` file) it is an ordinary React component: event handlers, refs and state work as usual. [In a client app](/docs/guides/static-or-interactive/#in-a-client-app).

## Text size on touch screens

Under a coarse pointer (a phone or a tablet), the value is 16 px (Label/L) instead of 14 px (Label/M)
at every size, as on the Select trigger, because iOS Safari zooms the page into a focused `<select>`
whose text is smaller than 16 px. The box keeps its 32, 40 or 48 px height.
`--nz-native-select-font` replaces the font on every pointer, so a page that sets it also decides
whether iOS zooms.
